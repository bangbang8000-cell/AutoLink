## 技能: 机房智能落位

当用户提出机房落位需求（如"225 柜按 120 GPU + 60 网络 + 45 存储落位，柱子别挡"、"按机柜落位"）时，按以下步骤执行：

1. **确认矩阵存在**：调用 `room_optimize`（参数 `project`，暂用 `counts` 为需求规模的简化值）探测项目是否有机房矩阵；若返回"无 room_layout.json"，且用户提供了矩阵规模（行/列数），调用 `room_create` 创建并落盘（参数 `rows`/`cols`/`project`），否则提示用户先在前端创建机房矩阵。
2. **类型域标记（可选）**：用户明确要求分区（如"网络柜集中到 D/E/F 列"、"GPU 高密度区靠空调"）时，先调用 `room_set_type` 标记专用区域类型（`project`/`position`/`type`），再做落位；"柱子/空调别挡"无需额外处理，优化器自动跳过占位格。
3. **解析数量**：从用户表述抽取类型→数量（GPU/网络/存储/通算），如"120 GPU + 60 网络 + 45 存储" → `{gpu:120, network:60, storage:45}`；歧义时（如"一些/尽量多"）向用户确认后再计算。
4. **生成方案**：调用 `room_optimize`（`project` + `counts`；用户给了具体机柜时可改传 `cabinets`）。方案仅计算不落盘。
5. **汇报并确认**：用自然语言汇报已落位/未放置数量、综合评分与关键 issues（如"位置不足"、"超功率未放置"），说明优化器已自动避开占位格；提示用户确认后由前端"应用方案"，应用后仍可手动拖拽调整。

注意事项：
- `room_optimize` 为 NOTIFY 权限：方案计算后需用户确认才应用，不要声称已落盘。
- `room_set_type` / `room_place` / `room_create`（带 project）为写操作（NOTIFY），执行后已落盘到项目矩阵，需在回复中说明修改结果。
- 修改矩阵后如用户继续提出落位需求，重新调用 `room_optimize`（会读取最新矩阵，保留手动放置）。
