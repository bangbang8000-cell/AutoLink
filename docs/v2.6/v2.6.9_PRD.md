## 二、问题清单与分析

### 问题 1: 暗色模式下中栏与工作区之间拖拽线是白色的

**现象**：暗色模式下，侧边栏和工作区之间的拖拽线（resize handle）显示为白色/亮灰色，与暗色背景形成强烈对比，视觉突兀。

**根因分析**：

[ResizableAppLayout.tsx#L61](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/layout/ResizableAppLayout.tsx#L61) 和 [L71](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/layout/ResizableAppLayout.tsx#L71) 使用 `dark:bg-edge-default`，但 Tailwind 中 `edge: { DEFAULT: '#484F58' }` 的 `DEFAULT` 键生成的是 `bg-edge`（无后缀），不是 `bg-edge-default`。`bg-edge-default` 类在 CSS 中不存在，因此回退到亮色模式的 `bg-gray-200`(#E5E7EB ≈ 白色)。

**修复方案**：将 `dark:bg-edge-default` 改为 `dark:bg-edge`。

**涉及文件**：`src/components/layout/ResizableAppLayout.tsx`（2 处）

### 问题 2: 检查到新版本后点击下载会失败

**现象**：更新弹窗中检测到新版本并显示"下载"按钮，点击后下载失败。

**根因分析**：

**根因 A — `latest.yml` 缺失**：

[build.yml#L47](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/.github/workflows/build.yml#L47) 使用 `--publish=never` 打包，`electron-builder` 不会生成 `latest.yml`。但 [update.service.ts#L27](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/electron/services/update.service.ts#L27) 的 `LATEST_YML_URL` 期望从 `https://github.com/.../releases/latest/download/latest.yml` 获取更新信息。没有 `latest.yml`，`electron-updater` 的 `downloadUpdate()` 无法知道要下载哪个文件。

**根因 B — fallback 路径的 `downloadUpdate()` 不可用**：

当 `electron-updater.checkForUpdates()` 失败、走 fallback 路径时，版本检测成功了但 `electron-updater` 内部没有缓存 `updateInfo`。`downloadUpdate()` 调用 `updater.downloadUpdate()` 会抛出 "No update info" 之类的错误。虽然有 `refillUpdaterInfoInBackground` 尝试后台重试填充缓存，但它是异步的，在用户点击下载时可能还未完成。

**修复方案**：

1. **build.yml 中手动生成 `latest.yml`**：在 Release 步骤中，根据已上传的安装包信息生成 `latest.yml` 文件，然后上传到 Release。确保 `latest.yml` 中的下载 URL 指向正确的 GitHub Release 资源。

2. **downloadUpdate 增加 fallback**：当 `electron-updater.downloadUpdate()` 失败时，不直接报错，而是回退到打开 GitHub Releases 页面让用户手动下载。

**涉及文件**：
- `.github/workflows/build.yml`（生成 latest.yml + 上传到 release）
- `electron/services/update.service.ts`（downloadUpdate 增加 fallback）
- `src/components/layout/UpdatePopover.tsx`（下载失败时提示手动下载）

### 问题 3: 项目浏览器中输出文件无法显示

**现象**：项目浏览器中，"输出文件" Section 和项目下的"输出文件"分组均无法显示每个项目 `output/` 目录下的渲染批次文件。也不确认文件是否可以加载到工作区。

**根因分析**：

经过代码审查，`listOutputBatches` 后端实现（[handlers.ts#L488-L502](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/electron/ipc/handlers.ts#L488-L502)）和前端调用链（`toggleProjectExpand` / `OutputSection.toggleProject`）逻辑正确。但存在以下潜在问题：

**根因 A — 文件路径不匹配导致 FileViewerTab 无法打开**：

`OutputSection` 中 `handleFileClick` 调用 `openTab` 时只传了 `filePath` 且 `isTemplate: false`，但 `WorkspaceView` 中 `FileViewerTab` 的路径拼接逻辑（[WorkspaceView.tsx#L86-L99](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/WorkspaceView.tsx#L86-L99)）会在 `projectName` 存在时自动拼接 `projectName/filePath`。如果 `filePath` 已经包含 `projectName` 前缀（如 `${projectName}/output/batch/file.xlsx`），会导致路径重复。

**根因 B — 项目内 output 分组的批次文件点击未传 projectName**：

`handleBatchFileClick` 中 `openTab` 的状态没有传 `projectName`，导致 `WorkspaceView` 中 `filePath` 拼接逻辑不生效（`projectName` 为 undefined，`rawFilePath` 直接使用）。

**修复方案**：

1. **统一 filePath 格式**：所有 output 文件的 `filePath` 统一使用项目相对路径（不含 `projectName` 前缀），在 `openTab` 时始终传入 `projectName`。
2. **修复 `handleBatchFileClick`**：传入 `projectName`。
3. **修复 `OutputSection.handleFileClick`**：传入 `projectName`，确保路径拼接正确。
4. **后端 `listOutputBatches` 返回的 path 改为相对路径**：将 `${projectName}/output/${batch}/${file}` 改为 `output/${batch}/${file}`。

**涉及文件**：
- `electron/ipc/handlers.ts`（`listOutputBatches` 返回的 path 格式）
- `src/components/layout/FileExplorer.tsx`（`handleBatchFileClick`、`handleFileClick` 传 `projectName`）
- `src/components/workspace/WorkspaceView.tsx`（`FileViewerTab` 路径拼接逻辑）

## 四、风险与缓解

| 风险 | 缓解 |
|------|------|
| `latest.yml` 格式生成错误，导致 electron-updater 解析失败 | 参照 electron-builder 标准格式，手动构造并验证 |
| filePath 格式变更导致已有文件打开异常 | 只修改 output 相关路径，不改变已有的项目文件/模板文件路径 |
| listOutputBatches 修改后与 OutputSection 不兼容 | OutputSection 也使用同一路径格式，同步修改 |
