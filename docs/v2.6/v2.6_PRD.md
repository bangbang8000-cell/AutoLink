# AutoLink v2.6.X 产品需求文档(PRD)

> **版本**:v2.6.X(分版本发布:v2.6.0 紧急修复 → v2.6.1 体验完善 → v2.6.2 质量与增强)
> **日期**:2026-07-30
> **作者**:AutoLink Team
> **状态**:待评审 → 评审通过后进入开发
> **范围**:用户反馈 8 项缺陷修复 + v2.5 遗留 P0/P1/P2 问题 + 关键体验增强
> **配套文档**:[v2.5_验收与质量评估报告.md](./v2.5_验收与质量评估报告.md)、[v2.6_Development_Plan.md](./v2.6_Development_Plan.md)

---

## 1. 背景

v2.5.0 发布后,用户下载编译版本进行实测,反馈 8 项问题(用户明确表示"只是一小部分"),并对程序整体质量提出系统性评估与提升要求。经全面代码审计,除用户反馈的 8 项外,还发现 5 项 P0(类型/接口不一致导致的运行时 bug)、10 项 P1(死代码、ErrorBoundary 缺失、状态管理)、14 项 P2(代码质量)问题。

v2.6.X 聚焦"修复实测缺陷 + 消除隐藏 bug + 补齐体验短板",不引入大规模新业务功能,为 v2.7 的功能扩展打基础。

---

## 2. 版本划分策略

鉴于问题数量多、严重程度差异大,采用三段式分版本发布,确保紧急问题快速修复、体验问题系统完善:

| 版本 | 主题 | 范围 | 优先级 |
|---|---|---|---|
| **v2.6.0** | 紧急缺陷修复 | 用户反馈 8 项 + P0 隐藏 bug | 最高,优先发版 |
| **v2.6.1** | 体验完善与死代码清理 | P1 问题 + 向导滚动 + 关键 i18n 补齐 | 高 |
| **v2.6.2** | 质量提升与功能增强 | P2 代码质量 + 本地用户指南 + 从模板创建 | 中 |

## 4. 详细需求

### R1:修复多语言机制(P0,v2.6.0)

#### 4.1.1 缺陷描述
1. **device 命名空间 4 语言缺失**:`en/ja/ko/zh-TW` 的 `index.ts` 未引用 `device.json`,非中文用户访问 `device:*` 翻译键时回退失败,影响 10+ 设备库相关组件
2. **启动语言不同步**:`i18n/index.ts` 硬编码 `lng: 'zh-CN'`,不读取 `ui.store` 持久化的 `language`,刷新后选中态与实际语言错位
3. **硬编码中文**:约 6 个组件完全未走 i18n(MenuBar/WorkspaceWelcome/WorkspaceTabBar/WorkspaceView/DeviceLibraryTab 等)

#### 4.1.2 修复方案
1. 4 个语言 `index.ts` 补充 `import device from './device.json'` 并导出
2. `App.tsx` 添加 `useEffect` 监听 `ui.store.language`,启动时调用 `i18n.changeLanguage` 同步;或 `i18n/index.ts` 从 localStorage 读取
3. v2.6.0 先补齐关键硬编码(SettingsPanel/FileExplorer 右键菜单/WorkspaceView 卡片),v2.6.1 完成 MenuBar i18n 化(R17)

#### 4.1.3 验收条件
1. 切换到英文后刷新,UI 仍为英文(选中态与实际语言一致)
2. 5 种语言下 `device:*` 翻译键均正常显示,无 key 字符串泄露
3. SettingsPanel/FileExplorer 右键菜单/WorkspaceView 卡片文案随语言切换

### R4:向导对话框滚动机制(P0,v2.6.0)

#### 4.4.1 缺陷描述
新建项目向导对话框在步骤3(设备选型)和步骤5(确认)内容过多时,超出屏幕高度,底部"下一步/确认"按钮被裁切不可见。

#### 4.4.2 根因
- 模态缺 `overflow-hidden`,内容视觉溢出模态边界
- 高度链 `h-full` 依赖不成立,`overflow-y-auto` 未正确触发
- Header/步骤指示器/底部按钮栏缺 `shrink-0`,可能被压缩

#### 4.4.3 修复方案
1. `CreateProjectWizardModal.tsx` 模态添加 `overflow-hidden`
2. 中间容器改为 `flex-1 min-h-0 flex flex-col`,ProjectWizard 根 div 改 `flex-1 min-h-0` 替代 `h-full`
3. Header/步骤指示器/底部按钮栏全部加 `shrink-0`
4. 底部按钮栏加 `sticky bottom-0 bg-white dark:bg-gray-800` 保险

#### 4.4.4 验收条件
1. 800px 高屏幕下,步骤3/步骤5 内容可内部滚动,底部按钮始终可见
2. 对话框不超出视口,上下留可见边距

### R5:设备选型 IB/RoCE 联动(P0,v2.6.0)

#### 4.5.1 缺陷描述
用户在向导选择 IB 协议后,参数网交换机正确切换为 NVIDIA IB 系列,但**存储交换机仍硬编码为 `h3c_s6850_56hf`(RoCE 交换机)**,不随协议联动。

#### 4.5.2 根因
- `backend/migration.py:183-185` 存储交换机分支无条件硬编码,不像 param_* 那样按 `protocol` 分流
- `src/components/wizard/WizardStepDevices.tsx:50-53` `STORAGE_DEFAULTS` 无协议区分
- `WizardStepDevices.tsx:192-209` 协议切换联动只检查 `param_leaf_switch`,忽略 `storage_leaf_switch`
- `backend/designer.py` 不做兜底校验

#### 4.5.3 修复方案
1. `migration.py:183-185` 按 `protocol` 分流:IB 时 storage 改为 IB 存储交换机(补设备库,如 NVIDIA SN5600/SN4700),RoCE 时维持
2. `WizardStepDevices.tsx` `STORAGE_DEFAULTS` 改为 `STORAGE_DEFAULTS_BY_PROTOCOL`,区分 IB/RoCE
3. 协议切换联动判定纳入 `storage_leaf_switch`
4. `designer.py._create_storage_switches()` 加校验:`param_protocol=='IB'` 但 storage profile 非 IB 时警告
5. 设备库补齐 IB 存储交换机选项

#### 4.5.4 验收条件
1. 选择 IB 协议后,存储交换机自动切换为 IB 型号
2. 选择 RoCE 协议后,存储交换机为 RoCE 型号
3. 切换协议时,storage 开关联动更新(若用户未手动改过)

### R7:一键渲染修复(P0,v2.6.0)

#### 4.7.1 缺陷描述
项目概览页"快速操作→一键渲染"点击后,打开空白输出结果页签,显示"无法预览此文件"。

#### 4.7.2 根因
1. `ProjectOverviewTab.tsx:114-116` `handleQuickRender` **根本没触发渲染**,只 `openTab({ type: 'output' })`,未传 fileName/fileType,也未调用任何渲染 IPC
2. `OutputTab.tsx:32/52` 调用 `getFileBinary(fileName)` 只传 1 个参数,正确签名是 `getFileBinary(projectName, filePath)`,且 `fileName` 缺少 `output/` 前缀

#### 4.7.3 修复方案
方案 A(最小改动,推荐 v2.6.0):`handleQuickRender` 改为跳转到工作台页签,提示用户使用工作台真正的一键渲染按钮
方案 B(完整实现,v2.6.2 增强):`handleQuickRender` 真正执行渲染:
1. 调用 `render.exportConnections(projectName, ['connections','deviceList'])`
2. 监听 `render:progress` 等待完成
3. `listOutputFiles(projectName)` 刷新
4. 打开 output 页签传入 `state: { fileName, fileType, projectName }`

同时修复 `OutputTab.tsx` 的 `getFileBinary` 调用:从 `useProjectStore` 获取 `selectedProjectName`,调用 `getFileBinary(projectName, 'output/' + fileName)`

#### 4.7.4 验收条件
1. 点击"一键渲染"不再显示空白"无法预览此文件"
2. 方案 A:跳转工作台,提示用户操作
3. 方案 B:真正触发渲染,完成后展示结果文件

### R9:preload/electron.d.ts 类型对齐(P0,v2.6.0)

#### 4.9.1 缺陷描述
4 处 preload 实现与 electron.d.ts 声明不一致,TypeScript 编译通过但运行时行为异常:

| 问题 | 声明 | 实现 |
|---|---|---|
| `dialog.openDirectory` | electron.d.ts 声明可选 | preload **完全未实现**,Settings 页面调用静默失效 |
| `getFileBinary` 返回类型 | `Promise<Uint8Array \| null>` | handlers 返回 `buffer.toString('base64')`(string) |
| `device-library:export` 返回类型 | `Promise<void>` | handlers 返回 string/object |
| `versions` 字段 | electron.d.ts 无 chromium | preload 暴露 chromium |

#### 4.9.2 修复方案
1. `preload.ts` 暴露 `dialog.openDirectory`,`handlers.ts` 注册 `dialog:openDirectory` 调 `dialog.showOpenDialog`
2. `getFileBinary` 类型对齐:统一为 `Promise<string | null>`(base64),handlers 与 electron.d.ts 同步
3. `device-library:export` 返回类型对齐:electron.d.ts 改为 `Promise<string | { devices: unknown[]; format: string }>`
4. `versions` 类型补 chromium 字段

#### 4.9.3 验收条件
1. Settings 页面"输出目录选择""设备库数据目录选择"按钮可用
2. 二进制文件预览(图片/PDF)正常
3. 设备库导出数据不丢失
4. `versions.chrome` 可访问

### R10:shell:openPath/showItemInFolder 路径校验放宽(P0,v2.6.0)

#### 4.10.3 验收条件
