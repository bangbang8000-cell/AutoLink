## 二、用户实测反馈 8 项问题根因排查

### 问题 1:多语言机制有问题

**根因**:
1. `src/i18n/resources/{en,ja,ko,zh-TW}/index.ts` **未引用 device.json**,只有 zh-CN 引用 → 非中文用户 device 命名空间翻译键回退失败,影响 10+ 设备库组件
2. `src/i18n/index.ts:18` 硬编码 `lng: 'zh-CN'`,不读取 ui.store 持久化的 language → 切换语言后刷新,选中态与实际语言错位
3. 约 6 个组件完全未走 i18n(MenuBar/WorkspaceWelcome/WorkspaceTabBar/WorkspaceView/DeviceLibraryTab 等)

**修复**:v2.6.0 R1(device 命名空间补齐 + 启动语言恢复 + 关键硬编码),v2.6.1 R17(MenuBar i18n)

---

### 问题 2:打开用户指南要加载到本地工作区,不是跳转线上链接

**根因**:
1. 3 处"使用指南"入口(WorkspaceView 卡片/MenuBar 菜单/AboutDialog 链接)全部走 `shell.openExternal` 跳 GitHub Wiki
2. 欢迎页卡片还**错跳仓库主页**(非 wiki)
3. 仓库**无面向终端用户的指南 markdown**,extraResources 未打包任何用户文档
4. 工作区**无 markdown 预览 Tab 类型**,package.json 无 react-markdown 依赖

**修复**:v2.6.2 R2(本地 markdown 内容 + 打包 + IPC + GuideTab + react-markdown + 入口替换)

---

### 问题 3:关于弹窗内容不符合预期

**根因**:见第一节 R2 偏差详情

**修复**:v2.6.0 R3

---

### 问题 4:向导对话框超过屏幕,看不见下一步和确认按钮

**根因**:
1. `CreateProjectWizardModal.tsx:46` 模态有 `max-h-[85vh]` 但**缺 `overflow-hidden`**,内容视觉溢出模态边界
2. 高度链 `h-full` 依赖不成立(`flex-1 min-h-0` 父容器在 max-height 约束下可能解析为 auto),`overflow-y-auto` 未正确触发
3. Header/步骤指示器/底部按钮栏**缺 `shrink-0`**,可能被 flex 压缩
4. 步骤3(设备选型)全启用网络时内容 500-700px,步骤5(确认)550-750px,加固定区可达 750-900px,超 800px 屏幕的 680px 模态上限

**修复**:v2.6.0 R4(overflow-hidden + 高度链加固 + shrink-0 + sticky footer)

---

### 问题 5:选了 IB,存储还是推荐 RoCE

**根因**:
1. `backend/migration.py:183-185` 存储交换机分支**无条件硬编码** `h3c_s6850_56hf`,不像 param_*(174-181 行)那样按 protocol 分流
2. `src/components/wizard/WizardStepDevices.tsx:50-53` `STORAGE_DEFAULTS` 无协议区分
3. `WizardStepDevices.tsx:192-209` 协议切换联动**只检查 param_leaf_switch**,忽略 storage_leaf_switch
4. `backend/designer.py._create_storage_switches()` 不做兜底校验
5. IB 存储交换机设备库缺位(switches_storage 下仅 nvidia_sn4600c 一款 100G IB)

**修复**:v2.6.0 R5(migration.py 分流 + STORAGE_DEFAULTS_BY_PROTOCOL + 联动纳入 storage + designer 校验 + 设备库补充)

---

### 问题 6:6850 被误认为是 200G 交换机,业务交换机选型也有问题

**根因**:
1. `template/device_library/switches/storage/h3c_s6850_56hf.json` **纯数据录入错误**:实际是 25G 业务接入交换机(SFP28),被录成 200G 存储(QSFP56);category/port_speed/port_type/description/tags/applicable_networks 全错,物理文件也放错目录
2. `library_index.json:110` 把 `huawei_ce6860_48s6cq` 列在 switches_storage,但文件实际在 switches/biz/ 目录且 category=switches_biz → **该设备在任何分类都不可见**(加载失败)
3. 设备库**无一致性校验**,类似错误静默存在
4. 业务交换机默认 `biz_access_switch = 'h3c_s5560x_54s_ei'`(10G 设备),但 `biz_port_speed='25G'` → **设备与配置速率错配**
5. biz 选型逻辑**完全不读设备 port_speed/port_count**,纯按 INI/JSON 拓扑参数算

**修复**:v2.6.0 R6(6850 全字段修正 + ce6860 归属修正 + 一致性校验 + 全库审计 + 业务默认改 25G)

---

### 问题 7:一键渲染打开空白输出页签,显示"无法预览此文件"

**根因**:
1. `src/components/workspace/tabs/ProjectOverviewTab.tsx:114-116` `handleQuickRender` **根本没触发渲染**,只 `openTab({ type: 'output' })`,未传 fileName/fileType,也未调用任何渲染 IPC
2. `src/components/workspace/tabs/OutputTab.tsx:32/52` 调用 `getFileBinary(fileName)` **只传 1 个参数**,正确签名是 `getFileBinary(projectName, filePath)`,且 fileName 缺少 `output/` 前缀
3. fileName 为空时 OutputTab `useEffect` 直接 return,所有状态保持初始值,落入"无法预览此文件"分支

**修复**:v2.6.0 R7 方案 A(跳工作台 + OutputTab 参数修复),v2.6.2 R7 方案 B(完整实现真触发渲染)

---

### 问题 8:项目浏览器全部项目/输入文件/模板中心选择后无法查看文件列表

**根因**:
1. `FileExplorer.tsx:55-66` `handleOpenProject` 只调 `selectProject + openTab(projectOverview)`,**从不调用 `project:getStructure` IPC**(该 IPC 已实现但属死代码)
2. **"输入文件" Section 在代码中根本不存在**(只有"全部项目""输出文件""模板中心")——用户记忆与实际混淆
3. OutputSection/TemplateSection 的展开状态(expandedProjects/batchesMap/expandedTemplates/structureMap)是**组件内 useState,未进 store**,关闭侧栏再开列表折叠
4. "加载到工作区"对输出/模板文件已通过 FileViewerTab 实现,但对项目自身文件未实现(无文件树点击入口)

**修复**:v2.6.0 R8(getStructure 调用 + 文件树展开 + 输入文件 Section + 状态提升 explorer.store)

## 五、关键结论

1. **v2.5 PRD 完成度高**:R1-R7 全部完成,R2 有 2 处小偏差(已纳入 v2.6.0 修复)。核心缺陷修复(R4-R7)实现质量良好。

2. **用户反馈 8 项问题根因全部定位**:多为硬编码遗漏(migration.py storage 分支、STORAGE_DEFAULTS)、死代码未调用(getStructure)、参数传递错误(OutputTab getFileBinary)、数据录入错误(6850)、类型不一致(preload 4 处)。

3. **隐藏的 P0 bug 更危险**:preload 与 electron.d.ts 的 4 处不一致(P0-1/2/3/6)是 TypeScript 编译通过但运行时异常的隐藏 bug,优先修复。

4. **死代码清理时机已到**:sidebar/ 9 文件 + WorkspaceTabBar/Welcome 共 11 个死代码文件,虽 PRD 延后 v2.6,但当前会误导维护者,v2.6.1 提前清理。

5. **v2.6.X 三段式发布策略**:v2.6.0 紧急修复(10d)→ v2.6.1 体验完善(7.5d)→ v2.6.2 质量增强(6d),确保紧急问题快速发版,体验问题系统完善。
