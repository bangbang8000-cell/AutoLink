# AutoLink v2.6.8 — UI 视觉系统重构 PRD

> 版本:v2.6.8 | 状态:待评审 | 作者:AI 助手 | 日期:2026-07-31

## 一、背景与目标

### 1.1 现状问题

v2.6.7 完成了功能层面的多项迭代,但 UI 视觉层面存在系统性问题,直接影响用户日常使用体验:

1. **暗色模式色阶层次缺失(最严重)**:Tailwind 默认 gray 色阶在暗色端(gray-900/800/700)亮度差仅 10-15 单位,导致"点线面"融为一体——侧边栏与内容区无法区分、卡片与背景混淆、分隔线不可见。用户反馈"暗色模式有点偏黑"。
2. **色彩使用过于保守**:全界面几乎只用 gray 色阶 + primary 蓝色,语义色(success/error/warning/info)仅在 Toast 中使用。图标全灰,无法通过颜色快速识别功能。
3. **空间感缺失**:所有卡片/面板/区域使用相同的"border + rounded + bg-white/dark:bg-gray-800"处理,无阴影、无浮起感、无层次区分。
4. **排版可读性不足**:`text-2xs`(10px)和`text-3xs`(9px)在 2K/4K 显示器上过小;标题与正文仅靠字号区分,缺乏字重变化;技术数据未使用等宽字体。
5. **交互反馈单调**:按钮/开关/菜单/标签页切换无过渡动画,hover 效果仅背景色变化,调整手柄太细难以定位。
6. **组件细节不一致**:Button 的 size 未统一使用、Toggle 大小无差异、部分地方使用原生 select 而非组件。

### 1.2 目标

本轮 v2.6.8 聚焦 **UI 视觉系统重构**,核心目标:

1. **暗色模式色阶重构**:从 Tailwind 默认 gray 切换为自定义色阶,定义 3 层语义背景色(`bg-app`/`bg-surface`/`bg-elevated`),确保暗色模式下"点线面"清晰可辨
2. **色彩语义化**:图标/状态指示器/导航入口使用语义色,让颜色成为信息传达的载体
3. **空间层次建立**:卡片增加阴影/ring 浮起感,区域之间通过亮度差异区分层次
4. **排版优化**:提升最小字号、增加字重变化、技术数据使用等宽字体
5. **动效规范化**:统一过渡动画时长和缓动函数,为菜单/Dropdown 添加入场动画
6. **组件细节修复**:调整手柄加宽、分隔线可见度提升、按钮尺寸统一

### 1.3 非目标

- 不改变整体布局架构(ActivityBar + Sidebar + Workspace 三栏式)
- 不改变任何业务逻辑
- 不引入新功能
- 不重写 Tailwind 配置为 v4(保持 v3)
- 不引入新的 UI 组件库

## 二、暗色模式色阶重构(核心)

### 2.1 当前问题量化分析

| 元素 | 当前 Tailwind 类 | 色值 | 与其他元素的亮度差 |
|------|-----------------|------|-------------------|
| 主背景 | `bg-gray-900` | #111827 | — |
| 侧边栏/内容区 | `bg-gray-800` | #1F2937 | 与主背景差 14 |
| 头部 | `bg-gray-900` | #111827 | 与主背景差 0 |
| 状态栏 | `bg-gray-800` | #1F2937 | 与内容区差 0 |
| 分隔线 | `border-gray-700` | #374151 | 在 gray-800 上 ΔE≈8,几乎不可见 |
| 卡片 | `bg-gray-800` | #1F2937 | 与内容区差 0 |
| 悬停 | `hover:bg-gray-700` | #374151 | 与 gray-800 差 18 |

**根本问题**:Tailwind gray 色阶在暗端过于密集,`gray-900`→`gray-800`→`gray-700` 的亮度差不足以支持 UI 层次。

### 2.2 目标色阶方案

采用 GitHub 暗色风格为参考,定义三层语义背景色:

```
层级                  自定义色值        Tailwind 参考       用途
─────────────────────────────────────────────────────────────────
bg-app (最深)        #0D1117          ≈ slate-900        主背景、头部
bg-surface (中间)    #161B22          ≈ gray-925(新)     侧边栏、标签栏
bg-elevated (最浅)   #1C2333          ≈ gray-875(新)     内容区、卡片
bg-hover             #252D3A          ≈ gray-825(新)     悬停态
border-subtle        #30363D          ≈ gray-750(新)     细微分隔线
border-default       #484F58          ≈ gray-650(新)     可见边框
```

**亮度差对比**:
- `bg-app` → `bg-surface`:差 14 → 与旧 gray-900→gray-800 相同,但起点更深
- `bg-surface` → `bg-elevated`:差 17 → 清晰可辨
- `bg-elevated` → `bg-hover`:差 20 → 悬停效果明显
- `border-subtle` 在 `bg-surface` 上:ΔE≈25 → 明显可见
- `border-default` 在 `bg-elevated` 上:ΔE≈35 → 清晰分隔

### 2.3 Tailwind 配置扩展

```js
// tailwind.config.js 新增
colors: {
  // 暗色模式语义色
  app: {
    DEFAULT: '#0D1117',    // bg-app
    surface: '#161B22',    // bg-surface
    elevated: '#1C2333',   // bg-elevated
    hover: '#252D3A',      // bg-hover
  },
  border: {
    subtle: '#30363D',     // 暗色细微分隔
    DEFAULT: '#484F58',    // 暗色可见边框
  },
}
```

### 2.4 亮色模式保持不变

亮色模式的 gray-50/100/200 色阶层次清晰,本轮不做调整。亮色模式仅受益于卡片阴影/动画等通用改进。

## 六、排版优化

### 6.1 字号调整

[tailwind.config.js](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/tailwind.config.js) 字号定义调整:

| Token | 当前 | 目标 | 用途 |
|-------|------|------|------|
| `text-3xs` | `['9px', '12px']` | `['10px', '13px']` | 徽章/计数 |
| `text-2xs` | `['10px', '14px']` | `['11px', '15px']` | 次要信息/时间戳 |

### 6.2 等宽字体应用

技术数据(端口号、IP 地址、速率、配置值)使用 `font-mono tabular-nums`:

- 拓扑概览中的节点数/连接数统计
- 设备库中的端口数/速率
- 键盘快捷键显示
- 配置参数值(NumberInput 组件)

### 6.3 字重层级

在 `SectionCard` 标题和页面级标题中增加 `font-bold` 使用,形成明确的三级字重:

```
font-bold   → 页面标题、卡片标题
font-semibold → 段落标题、重要标签
font-medium → 正文强调
font-normal → 正文
```

## 十、风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 暗色色阶替换范围大,遗漏组件 | 全局搜索 `dark:bg-gray-900`/`dark:bg-gray-800`/`dark:border-gray-700` 逐一替换,建立 checklist |
| 新色阶与拓扑可视化颜色冲突 | 拓扑可视化使用独立颜色常量(topology-colors.ts),不受 UI 色阶影响 |
| 亮色模式被误改 | 所有改动仅涉及 `dark:` 前缀,亮色模式代码路径不变 |
| 过渡动画影响性能 | 仅使用 CSS transition,不使用 JS 动画库,低端设备无性能影响 |
| 字号调整导致布局溢出 | 仅调整 2xs/3xs 两个极小字号,对布局影响可控,逐文件检查 |
