# AutoLink v2.6.3 — UI 系统优化 PRD 与开发计划

> 版本:v2.6.3 | 状态:待评审 | 作者:AI 助手 | 日期:2026-07-31

---

## 一、背景与目标

v2.6.2 完成了拓扑持久化、更新功能、关于对话框等核心功能修复。在功能稳定后,本轮 v2.6.3 聚焦 **UI 体验系统优化**,解决前期快速迭代遗留的视觉不一致、信息密度不足、代码冗余等问题。

### 核心目标
1. **信息密度增强**:项目浏览器从"纯名称列表"升级为"卡片式信息展示",让用户一眼看到项目状态/文件数/时间
2. **视觉一致性**:收敛字号梯度、统一间距/圆角/颜色规范,消除"看起来杂乱"的视觉噪音
3. **代码健康度**:删除死代码、抽象通用组件、补齐 i18n,降低后续维护成本

### 非目标
- 不改变整体布局架构(ActivityBar + Sidebar + Workspace 三栏式)
- 不引入新功能(仅优化已有界面的呈现)
- 不重写任何业务逻辑

## 四、详细设计

### U1:项目浏览器信息密度增强

#### U1.1 项目项卡片化

**现状**:`TreeItem` 仅显示 `p.name`,无状态/时间/文件数

**方案**:项目列表项从"纯文本树项"升级为"紧凑卡片"(保持可展开文件树能力)

卡片布局(单行,高度约 40px):
```
┌─────────────────────────────────────────────────────────┐
│ [状态点] 项目名称              [文件数] [时间] [★] [⋮] │
│         描述(可选,truncate)                           │
└─────────────────────────────────────────────────────────┘
```

字段:
- **状态点**:8px 圆点,4 种颜色
  - `ready` = gray(未配置)
  - `configured` = blue(已配置)
  - `designed` = primary(已设计)
  - `layouted` = green(已布局)
- **项目名称**:`text-xs font-medium`,truncate
- **文件数**:`text-[10px] text-gray-400`,格式如 "12 文件"(通过 `getStructure` 统计,缓存)
- **时间**:`text-[10px] text-gray-400`,相对时间(刚刚/3天前/2周前),tooltip 显示完整时间
- **收藏星标**:hover 显示,收藏态常驻
- **更多按钮**:hover 显示,点击弹出右键菜单(替代当前右键触发)

**数据源**:
- 状态:消费已有的 `projectStatuses`(需后端补充分区扫描逻辑,或前端基于文件存在性推断)
  - 推断规则:有 `network_config.ini` = configured;有 `topology.json` = designed;有 `rack_layout.json` = layouted;否则 = ready
- 文件数:复用 `getStructure` 返回的树,前端递归统计(缓存到 store,避免重复计算)
- 时间:读取项目目录的 `mtime`(需新增 IPC `project:getMeta` 返回 `{ mtime, fileCount }`,或在 `project:list` 中一并返回)

**权衡**:
- 若后端改动成本高,文件数/时间可在首次展开项目时才加载(懒加载),卡片初始只显示名称+状态点
- 推荐方案:扩展 `project:list` 返回值,增加 `status`/`fileCount`/`updatedAt` 字段(一次 IPC 拿全)

#### U1.2 输出文件图标

**现状**:`ExpandableTreeItem` 纯文本无图标

**方案**:新增 `getFileIcon(fileName)` 函数,按扩展名返回 lucide 图标:
- `.xlsx` / `.csv` → `FileSpreadsheet`(绿色)
- `.png` / `.jpg` / `.svg` → `Image`(蓝色)
- `.json` / `.txt` / `.md` → `FileText`(灰色)
- `.html` → `FileCode`(橙色)
- 其他 → `File`(灰色)

图标尺寸 12px,与文本基线对齐。

#### U1.3 模板项卡片化

**现状**:仅显示 `tpl.name`

**方案**:模板项卡片化(与项目卡片风格一致),显示:
```
┌────────────────────────────────────────────┐
│ [📋] 模板名称                    [内置] [⋮]│
│      描述(truncate)                       │
│      [标签1] [标签2]                       │
└────────────────────────────────────────────┘
```

字段:
- **图标**:`LayoutTemplate` 12px
- **名称**:`text-xs font-medium`
- **描述**:`text-[10px] text-gray-400`,truncate
- **内置徽章**:`text-[9px] bg-gray-100 px-1 rounded`,仅 `isBuiltin` 显示
- **标签**:`text-[9px] bg-primary-50 text-primary-600 px-1 rounded`,最多 2 个

### U2:关于界面排版优化

### U4:全局字体体系统一

**方案**:

1. **定义字号 Token**(在 tailwind.config.js `theme.extend.fontSize`):
   ```js
   fontSize: {
     'xs': ['10px', '14px'],      // 原 text-[10px],次要信息
     'sm': ['12px', '16px'],      // 原 text-xs,主导正文
     'base': ['13px', '18px'],    // 新增,中等正文
     'md': ['14px', '20px'],      // 原 text-sm,按钮/输入框
     'lg': ['16px', '22px'],      // 原 text-base,卡片标题
     'xl': ['18px', '24px'],      // 原 text-lg,页面标题
     '2xl': ['24px', '32px'],     // 原 text-2xl
   }
   ```
   
   **注意**:此改动会改变现有 `text-xs`/`text-sm`/`text-base` 的语义,需全局批量替换。为降低风险,采用**渐进式**:保留现有语义,新增 `text-2xs`(10px)/ `text-3xs`(9px)别名,逐步迁移。

2. **收敛细字号**:
   - `text-[10px]` (152次) → `text-2xs`(新 token)
   - `text-[11px]` (96次) → `text-2xs`(合并到 10px,11px 与 10px 视觉差异极小)
   - `text-[9px]` (14次) → `text-3xs`(新 token)
   - `text-[8px]` (2次) → `text-3xs`
3. **配置中文字体**:
   ```js
   fontFamily: {
     sans: ['-apple-system', 'BlinkMacSystemFont', '"Segoe UI"', 'Roboto',
            '"PingFang SC"', '"Microsoft YaHei"', '"Hiragino Sans GB"',
            '"Source Han Sans CN"', 'sans-serif'],
   }
   ```
4. **移除 CSS 变量**:删除 `style.css` 中未使用的 `--color-surface` 等 6 个变量(组件全部用 Tailwind 类),仅保留 `--font-size-base`(供设置面板字号调节)
5. **修复无效颜色类**:`gray-750` → `gray-700`、`gray-850` → `gray-800`(5 处)
