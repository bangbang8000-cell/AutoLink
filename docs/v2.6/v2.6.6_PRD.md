# AutoLink v2.6.6 — 项目浏览器树形重构 PRD

> 版本:v2.6.6 | 状态:待评审 | 作者:AI 助手 | 日期:2026-07-31

## 一、背景与目标

### 1.1 现状问题

当前 `FileExplorer.tsx`(约 1900 行)存在以下结构性问题:

1. **三套独立树结构**:`ProjectExplorer` / `OutputSection` / `TemplateSection` 各自维护展开状态、结构缓存、递归渲染函数,代码重复度高
2. **展开状态不持久化**:刷新或切换 Activity 后展开状态全部丢失,用户需重新展开
3. **层级单一**:项目下直接平铺文件,缺少"输入配置/输出文件/拓扑数据"等语义分组,用户难以快速定位
4. **交互不一致**:`ProjectExplorer` 单击=展开/双击=打开,`OutputSection` 单击=展开,`TemplateSection` 单击=展开,无统一约定
5. **右键菜单覆盖不全**:仅项目/模板根节点有右键菜单,文件节点和子目录节点无右键操作
6. **类型弱**:`project.getStructure` 返回 `unknown[]`,三层后类型丢失
7. **filePath 拼接不统一**:项目拼前缀、模板不拼、输出已是完整路径,易出错

### 1.2 目标

采用**方案 C:统一项目树 + 双分组模式**,将项目浏览器重构为 3 级树形结构(根 → 项目/模板 → 分组 → 文件),**同时支持"智能分组"和"真实分组"两种模式,用户可在配置中切换**,统一交互、持久化状态、补齐右键菜单。

### 1.3 非目标

- 不改变后端文件系统真实结构(仅前端展示层重构)
- 不改变项目/模板的创建/删除/导出等业务逻辑
- 不改变 `OutputSection` 的独立 Section 地位(保留集中查看所有输出)

## 二、目标树形结构

支持两种分组模式,用户可在「配置 → 项目浏览器」中切换。

### 2.1 智能分组模式(默认)

按文件**用途**虚拟分组,语义化分类,适合快速定位。

```
📂 全部项目                              ← Section(一级,可折叠)
  📂 H100-100台 ✦                        ← 项目节点(二级,单击=打开,箭头=展开)
    ▸ 📥 输入配置                         ← 智能分组(三级,虚拟节点)
      📄 network_config.ini
      📄 project_config.json
      📄 project.json
    ▸ 📤 输出文件                         ← 智能分组(三级)
      📂 2026-07-31_143000               ← 批次(四级,仅输出分组下)
        📄 connection_table.xlsx
        📄 topology.png
    ▸ 🗂 拓扑数据                         ← 智能分组(三级)
      📄 topology.json
      📄 rack_layout.json
    ▸ 📄 其他文件.txt                     ← 未归类文件(三级,直接展示)

📂 输出文件                              ← 独立 Section(保留)
  📂 H100-100台                          ← 项目节点(二级)
    📂 2026-07-31_143000                 ← 批次(三级)
      📄 connection_table.xlsx

📂 模板中心                              ← Section
  📂 H100-100台 [内置]                    ← 模板节点(二级)
    ▸ 📥 配置文件                         ← 智能分组(三级)
      📄 project_config.json
    ▸ 📄 其他文件
```

### 2.2 真实分组模式

完全模拟文件系统真实结构,所见即所得,适合了解项目实际布局。

```
📂 全部项目                              ← Section(一级,可折叠)
  📂 H100-100台 ✦                        ← 项目节点(二级,单击=打开,箭头=展开)
    ▸ 📂 output                          ← 真实子目录(三级,递归展示)
      📂 2026-07-31_143000               ← 批次(四级)
        📄 connection_table.xlsx
        📄 topology.png
    📄 network_config.ini                ← 根目录文件(三级,直接展示)
    📄 project_config.json
    📄 project.json
    📄 topology.json
    📄 rack_layout.json

📂 输出文件                              ← 独立 Section(保留,两种模式下均按批次展示)
  📂 H100-100台                          ← 项目节点(二级)
    📂 2026-07-31_143000                 ← 批次(三级)
      📄 connection_table.xlsx

📂 模板中心                              ← Section
  📂 H100-100台 [内置]                    ← 模板节点(二级)
    ▸ 📂 input                           ← 真实子目录(三级)
      📄 project_config.json
    📄 project.json
```

### 2.3 两种模式对比

| 维度 | 智能分组模式(默认) | 真实分组模式 |
|------|---------------------|--------------|
| 分组依据 | 文件用途(虚拟分组) | 文件系统真实目录 |
| 节点层级 | 固定 3-4 级(项目→分组→文件/批次) | 不固定(按真实目录深度递归) |
| 输出文件 | 归入"📤 输出文件"分组,按批次展示 | 作为 `output/` 真实目录展示,内部递归 |
| 隐藏文件 | 不显示 | 不显示(统一过滤) |
| 适用场景 | 快速定位配置/拓扑/输出 | 了解项目真实文件布局 |
| 切换方式 | 配置 → 项目浏览器 → 分组模式:智能分组 | 配置 → 项目浏览器 → 分组模式:真实分组 |

### 2.4 智能分组规则

| 分组 | 图标 | 匹配规则 | 适用 |
|------|------|----------|------|
| 📥 输入配置 | `FileInput` | `network_config.ini`、`project_config.json`、`project.json` | 项目、模板 |
| 📤 输出文件 | `FileOutput` | `output/` 目录下的所有内容(按批次子分组) | 项目 |
| 🗂 拓扑数据 | `Network` | `topology.json`、`rack_layout.json` | 项目 |
| 📄 其他文件 | `File` | 未归类的根目录文件 | 项目、模板 |

### 2.5 真实分组规则

- 完全按 `project:getStructure` / `template:getStructure` 返回的目录树递归展示
- 过滤 `.git` / `node_modules` / 隐藏文件(统一)
- 根目录文件与子目录平级展示
- 子目录递归展示其内容
- 不做任何语义化归类

### 2.6 分组行为(通用)

- 智能分组的"虚拟分组"节点不对应真实目录,仅用于 UI 分类
- 分组自动生成,用户无需手动创建
- 智能分组模式下,空分组(无匹配文件)**不显示**
- 真实分组模式下,空目录**显示**(与文件系统一致)
- 分组内文件按名称排序,批次按时间倒序
- **模式切换即时生效**,无需重启

## 四、技术方案

### 4.1 新建 `explorer.store.ts`

```typescript
// src/stores/explorer.store.ts
interface ExplorerState {
  // Section 折叠
  collapsedSections: Record<string, boolean>
  // 项目展开状态
  expandedProjects: Record<string, boolean>
  // 智能分组展开状态 key: `${projectName}/${groupName}`
  expandedGroups: Record<string, boolean>
  // 模板展开状态
  expandedTemplates: Record<string, boolean>
  // 输出批次展开状态 key: `${projectName}/${batchName}`
  expandedBatches: Record<string, boolean>
  // 结构缓存
  projectStructures: Record<string, FileTreeNode[]>
  templateStructures: Record<string, FileTreeNode[]>
  outputBatches: Record<string, OutputBatch[]>

  // Actions
  toggleSection: (section: string) => void
  toggleProject: (name: string) => void
  toggleGroup: (key: string) => void
  toggleTemplate: (name: string) => void
  toggleBatch: (key: string) => void
  setProjectStructure: (name: string, structure: FileTreeNode[]) => void
  setTemplateStructure: (name: string, structure: FileTreeNode[]) => void
  setOutputBatches: (name: string, batches: OutputBatch[]) => void
  cleanupProject: (name: string) => void  // 删除/重命名时清理
  resetAll: () => void
}
```

使用 `zustand` + `persist` 中间件持久化到 localStorage。

### 4.2 统一 `FileTreeNode` 类型

```typescript
// src/types/file-tree.ts
export interface FileTreeNode {
  name: string
  type: 'directory' | 'file'
  path: string                    // 相对根目录的路径
  size?: number
  updatedAt?: string
  children?: FileTreeNode[]

```

更新 `electron.d.ts` 中 `project.getStructure` 和 `template.getStructure` 的返回类型。

### 4.3 分组模式配置

```typescript
// src/stores/ui.store.ts 新增字段
type GroupMode = 'smart' | 'raw'   // smart=智能分组, raw=真实分组

interface UIState {
```

- 切换后即时刷新树形渲染(无需重启)
- 默认值:`'smart'`(智能分组)

### 4.5 真实分组渲染

真实分组模式直接使用 `renderTreeNodes` 递归渲染 `FileTreeNode[]`,无需分组函数处理。与智能分组的差异通过 `explorerGroupMode` 判断:
- `mode === 'smart'`:调用 `groupProjectFiles` → 渲染分组节点 → 渲染文件
- `mode === 'raw'`:直接调用 `renderTreeNodes` 递归渲染真实目录树

### 4.7 后端增强

#### `project:getStructure` 优化
- 过滤 `.git` / `node_modules` / 隐藏文件(统一与模板一致)
- 返回 `path` 字段(相对项目根的完整路径)
- 返回 `size` 和 `updatedAt`(可选,用于排序)

#### `template:getStructure` 优化
- 补充 `path` / `size` / `updatedAt` 字段(与项目统一)

#### filePath 拼接统一
- 项目文件:`filePath` = 相对项目根路径,fileViewer 内部拼 `${projectName}/${filePath}`
- 模板文件:`filePath` = 相对模板根路径,fileViewer 内部根据 `isTemplate` 走 `template.getFile`
- 输出文件:`filePath` = 完整路径(沿用现状)

## 六、风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 三套展开状态合并引发命名冲突 | 新建 `explorer.store.ts`,统一命名空间(`project:` / `template:` / `output:` 前缀) |
| filePath 拼接不统一导致文件打开失败 | 统一约定:项目文件拼前缀,模板/输出不拼,在 fileViewer 内部统一处理 |
| 智能分组与真实目录冲突(output 既是分组又是目录) | 智能分组为虚拟节点,不渲染真实 `output/` 目录节点,仅渲染分组下的批次/文件 |
| 重构范围大,引入回归 bug | 分阶段实施,每阶段独立测试;保持现有业务逻辑不变 |
