### 1.2 关键发现:Q2 和 Q3 的共同根因

**electron-updater 被错误地放在 `devDependencies`**(package.json:72),这同时导致:

1. **Q3 致命**:打包后 app.asar 内没有 electron-updater 模块,`import('electron-updater')` 抛 MODULE_NOT_FOUND → catch 静默返回 null → checkForUpdates 返回 `{updateAvailable: false}` → 前端显示"已是最新版本" → **更新功能完全失效**

2. **Q2 部分**:关于页面的软件栈中 `electronUpdater` 字段查 `deps['electron-updater']` → 在 dependencies 中找不到 → 显示 `-`(虽然此字段当前未显示在 UI 上,但相关代码存在隐患)

**修复方案**:将 electron-updater 从 devDependencies 移到 dependencies(1 行改动)

### 2.2 任务分解

#### T1: electron-updater 依赖位置修复 [P0 致命]
**解决问题**:Q3(更新功能失效)、Q2(软件栈 electronUpdater)、S1、S9

**改动**:
- package.json:将 `electron-updater` 从 devDependencies 移到 dependencies
- update.service.ts:`getAutoUpdater` 增加 dev 模式 `forceDevRunConfig` 支持(可选,用于开发环境测试)
- 新建 `dev-app-update.yml`(开发环境更新测试配置)

**验证**:
- 打包后确认 app.asar 内包含 electron-updater 模块
- 控制台不再出现 "electron-updater not available"

**复杂度**:低(代码改动 < 10 行,但需发布验证)

---

#### T2: 关于页面软件栈修复 [P0]
**解决问题**:Q2(软件栈 unknown)、S2、S3、S8

**改动**:
1. **路径修复**(handlers.ts `app:getStackVersions`):
   - 使用 `app.getAppPath()` 替代 `__dirname/../..` 读取 package.json
   - 确保打包后能读到 asar 内的 package.json

2. **依赖读取修复**:
   - `const allDeps = { ...pkg.dependencies, ...pkg.devDependencies }`
   - 统一读取所有依赖(T1 修复后 electron-updater 也在 dependencies)

3. **Python 检测增强**:
   - 增加 `py --version`(Windows py launcher)作为第三回退
   - 复用 pythonService 的 pythonPath 配置

4. **app:getVersion 路径同步修复**(handlers.ts:567-575,同样使用 `__dirname/../..`)

**验证**:
- 打包后关于页面显示完整的软件栈(AutoLink/Electron/Chromium/Node/React/TypeScript/Vite/ECharts/Python)
- 开发环境同样正常显示

**复杂度**:中

#### T5: 编辑菜单扩充 [P1]
**解决问题**:Q5

**改动**:
- common.json 5 语言:在 `menu.edit` 下补充 `undo/redo/cut/copy/paste/selectAll/find` key
- MenuBar.tsx Edit 菜单扩充为:
  ```
  撤销  Ctrl+Z
  重做  Ctrl+Y
  ---
  剪切  Ctrl+X
  复制  Ctrl+C
  粘贴  Ctrl+V
  ---
  全选  Ctrl+A
  查找  Ctrl+F
  ---
  首选项  Ctrl+,
  ```

**功能支撑策略**:
- **撤销/重做**:调用 `document.execCommand('undo'/'redo')`(浏览器原生,对文本输入生效);拓扑画布的撤销/重做后续 M3 提升
- **剪切/复制/粘贴**:调用 Clipboard API(`navigator.clipboard.writeText/readText`),对选中文本生效
- **全选**:`document.execCommand('selectAll')`
- **查找**:触发 `Ctrl+F` 事件(各组件已有监听则响应,无监听则 toast 提示)

**复杂度**:中(纯 UI + i18n 低,功能实现中)

---

#### T6: 拓扑数据按项目持久化 [P0 致命]
**解决问题**:Q4(核心)、S4、S5、S6

**改动清单**:

**6.1 Electron IPC 层**:
- handlers.ts:新增 `project:saveFile(projectName, relativePath, content)` IPC handler
  - 白名单:`topology.json`, `rack_layout.json`, `network_config.ini`
  - 路径安全:`path.basename` + 白名单校验
- preload.ts:暴露 `project.saveFile`
- electron.d.ts:添加类型定义
- project-io.service.ts:`ALLOWED_TOP_LEVEL` 集合添加 `topology.json` 和 `rack_layout.json`

**6.2 design.store.ts**:
- `loadSavedTopology`:改为读 `topology.json`(非 `topology_result.json`);失败时**清空** store(不残留上个项目)
- `generate`:生成成功后调用 `project.saveFile` 保存 topology.json(含 schema_version/config_snapshot/summary/topology/valid/estimation)
- persist partialize:移除 topology 字段持久化(改由项目文件持久化)

**6.3 rack.store.ts**:
- `saveRackLayout`:改写到项目根目录(非 output/);添加 schema_version 和 project_name
- `loadRackLayout`:路径对齐到项目根
- 在 RackPanel/RackTab 添加 `useEffect` 监听 cabinets 变化自动保存(防抖 500ms)
- persist partialize:移除 cabinets/unplacedDevices 持久化(改由项目文件持久化)

**6.4 project.store.ts**:
- `selectProject`:改为统一加载入口,异步调用 `loadConfig + loadSavedTopology + loadRackLayout`

**6.5 topology.json schema**:
```json
{
  "schema_version": 1,
  "project_name": "项目名",
  "generated_at": "ISO-8601",
  "config_snapshot": { ... },
  "summary": { ... },
  "topology": { "nodes": [...], "edges": [...] },
  "valid": true,
  "validationIssues": [],
  "estimation": { ... }
}
```

**验证**:
- 生成拓扑 → topology.json 出现在项目目录
- 切换项目 → 自动加载对应拓扑,无残留
- 重启应用 → 拓扑数据恢复
- 导出项目 ZIP → 包含 topology.json + rack_layout.json
- 导入项目 ZIP → 拓扑和机柜数据完整恢复
- 修改机柜布局 → 自动保存到 rack_layout.json

**复杂度**:中高(核心改动 4 文件 + 1 新 IPC + 1 白名单扩展)

**风险点**:
- 旧项目无 topology.json → 显示"尚未生成拓扑"(期望行为)
- rack.store localStorage 双源冲突 → 必须移除 partialize cabinets 持久化
- 加载时序 → selectProject 异步加载,组件可能短暂显示旧值(可接受)
