### T5:智能分组工具函数
**文件**:`src/utils/file-grouping.ts`(新建)

**内容**:
- 定义 `GroupKey` 类型:`'input' | 'output' | 'topology' | 'other'`
- 定义 `GroupedNode` 接口:`{ group: GroupKey; label: string; icon: LucideIcon; nodes: FileTreeNode[] }`
- `groupProjectFiles(structure: FileTreeNode[]): GroupedNode[]`:
  - input:匹配 `network_config.ini` / `project_config.json` / `project.json`
  - output:匹配 `output/` 目录下的内容(保留批次子目录结构)
  - topology:匹配 `topology.json` / `rack_layout.json`
  - other:未归类的根目录文件
  - 空分组过滤
  - 返回有序数组(input → output → topology → other)
- `groupTemplateFiles(structure: FileTreeNode[]): GroupedNode[]`:
  - input:匹配 `project_config.json` / `project.json`
  - other:未归类文件
  - 空分组过滤

**验证**:单元测试,验证分组规则、空分组过滤、排序

## 风险控制

| 风险 | 缓解 |
|------|------|
| 重构范围大(1900 行文件) | 分阶段实施,每阶段独立测试;保持业务逻辑不变 |
| explorer.store 持久化数据膨胀 | persist 配置 `partialize`,仅持久化展开状态(不持久化结构缓存) |
| 智能分组与 output/ 真实目录冲突 | smart 模式下分组为虚拟节点,不渲染真实 output/ 目录节点;raw 模式下 output/ 作为普通目录 |
| filePath 拼接回归 | T6 单独验证三种文件打开,再进行后续改造 |
| 双模式切换导致展开状态错乱 | smart 模式的展开 key 用 `group:` 前缀,raw 模式用 `dir:` 前缀,命名空间隔离 |
| 模式切换性能 | 切换时仅重新渲染树,不重新拉取结构(结构缓存复用) |
