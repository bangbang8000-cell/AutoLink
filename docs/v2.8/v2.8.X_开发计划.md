## v2.8.0 — 文件加载与查看

**目标**:Excel 秒开秒切、图片正确预览、输出文件列表统一。解决用户反馈第 1、2 条。

**关联需求**:R1.1 ~ R1.8,问题 E1/E2/F5/F6/U4/B1/B2/B3/B4。

### 任务分解

#### T1:抽取统一 ExcelTable 组件(一次加载全 sheet 缓存)
- **文件**:`src/components/workspace/ExcelTable.tsx`(新建,或在 tabs 下)
- **内容**:封装 Sheet 标签栏 + 表格渲染,props 接收 `sheets: Record<string, string[][]>` 与 `activeSheet`/`onChange`
- **说明**:从 OutputTab 的表格渲染部分提炼,样式保持一致(表头 sticky、斑马纹、暗色适配)
- **验收**:OutputTab 改用该组件渲染,行为不变

#### T2:FileViewerTab Excel 一次性加载全部 sheet
- **文件**:`src/components/workspace/tabs/FileViewerTab.tsx`
- **内容**:
  - state 由 `{ sheets, current, data }` 改为 `{ sheets: string[]; current: string; dataMap: Record<string, string[][]> }`
  - `loadFile` 仿照 OutputTab:一次 `wb.SheetNames.forEach(name => dataMap[name] = sheet_to_json(...))`
  - `switchSheet` 改为纯 `setExcelData(prev => prev ? { ...prev, current: name } : prev)` —— 无 IPC、无解析、无 loading 闪烁
- **验收**:多 sheet 大 Excel 切换即时;`switchSheet` 不再调用 IPC / XLSX.read

#### T3:消除 atob 逐字节解码
- **文件**:`src/components/workspace/tabs/FileViewerTab.tsx`(及 T2 改后的残留)
- **内容**:`getFileBinary` 返回 base64 后直接 `XLSX.read(base64, { type: 'base64' })`,删除 `atob` + `charCodeAt` 循环
- **验收**:FileViewerTab 无 `atob` 逐字节代码;大文件加载耗时下降

#### T4:模块级文件解析缓存
- **文件**:`src/utils/excel-cache.ts`(新建)+ FileViewerTab
- **内容**:模块级 `Map<string, Record<string, string[][]>>`(key = `${projectName}/${relPath}`),打开文件先查缓存,命中直接渲染;组件卸载不清缓存
- **验收**:关闭再打开同一 Excel 秒开,无"加载中";缓存可被同一项目路径复用

#### T5:FileViewerTab 图片分支(修复乱码)
- **文件**:`src/components/workspace/tabs/FileViewerTab.tsx`
- **内容**:
  - `isImage = ['png','jpg','jpeg','gif','webp'].includes(ext)` 与 `isSvg = ext === 'svg'`
  - 图片分支:走 `project.getFileBinary`,构造 `data:image/png;base64,...`(按扩展名映射 MIME)渲染 `<img>`
  - SVG 分支:`data:image/svg+xml;base64,...`
  - 非图片非 Excel 非 JSON 保持文本逻辑
- **验收**:输出区点击 PNG 显示图片;SVG 正常显示;不再出现二进制乱码

#### T6:listOutputFiles 小写化 + OutputTab 类型归一 + SVG 分支
- **文件**:`electron/ipc/handlers.ts`、`src/components/workspace/tabs/OutputTab.tsx`
- **内容**:
  - handlers L510:`type: path.extname(f.name).slice(1).toLowerCase() || 'file'`
  - OutputTab:所有比较统一 `String(fileType).toLowerCase()`;扩展名判断小写化;补 `svg` 分支(`data:image/svg+xml;base64,...`);MIME 用映射函数而非 fileType 直拼
- **验收**:`.PNG` 大写扩展名可预览;SVG 可预览;输出区图片 MIME 全小写

#### T7:输出区文件列表统一(拓扑 PNG 可见)
- **文件**:`src/components/layout/OutputSection.tsx`、`electron/ipc/handlers.ts`
- **内容**:
  - 方案 A(推荐):`listOutputBatches` 增加根目录文件为虚拟批次(如 `[根目录]`)或合并返回;OutputSection 渲染根文件
  - 或 OutputSection 额外调用 `listOutputFiles` 展示根目录文件区
- **验收**:导出拓扑 PNG 后,侧边栏"输出结果"区可见并可点击打开(图片预览)

#### T8:点击文件按扩展名分发
- **文件**:`src/components/layout/OutputSection.tsx`、`src/components/layout/ProjectListPanel.tsx`、`src/components/sidebar/OutputPanel.tsx`
- **内容**:统一 `openFileByExt(filePath, fileName, projectName)` 工具:`output/` 根文件走 `output` tab(带 fileType);批次文件图片走 `output` tab 或 fileViewer 图片分支;Excel/文本走 fileViewer
- **验收**:任意入口点击 png/svg → 图片预览;xlsx → 表格;json → JSON 文本

## v2.8.1 — 拓扑持久化与可加载

**目标**:拓扑(含用户布局)落盘项目文件,点击可加载继续编辑并保存。解决用户反馈第 3 条。

**关联需求**:R2.1 ~ R2.8,问题 F1/F4/B8。

### 任务分解

#### T1:topology.json schema v2 增加 layout 字段
- **文件**:`src/types/project-config.ts`(或 design.store 类型)、`src/stores/design.store.ts`
- **内容**:
  - 定义 `TopologyLayout = { version: 1; savedAt: string; nodePositions: Record<string, { x: number; y: number }> }`
  - 生成 payload 时 `schema_version: 2`,追加 `layout: null`(初始无)
- **验收**:generate 后 topology.json 含 `schema_version: 2` 与 `layout` 字段

#### T2:保存布局写入 topology.json
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`、`src/stores/design.store.ts`
- **内容**:
  - design.store 新增 `saveLayout(projectName, nodePositions)`:
    读现有 topology.json → 更新 `layout` 字段 → 经 `project:saveFile` 写回
  - `handleSaveLayout` 改为:先写 localStorage(快速恢复),再调 `saveLayout` 落盘
  - 按钮文案:"保存布局" → "保存到项目"(与 i18n 联动,v2.8.3 收敛)
- **验收**:点击保存后 topology.json 的 layout 包含全部设备节点坐标;刷新/重开项目后位置保留

#### T3:加载优先级:文件 layout > localStorage > 自动布局
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:`computedNodes` 生成位置时:文件 layout(需从 store 读取)→ localStorage → 自动布局坐标;三者均缺才用布局算法坐标
- **验收**:有文件 layout 时优先使用;无 layout 回退旧行为

#### T4:重新生成拓扑保留已保存 layout
- **文件**:`src/stores/design.store.ts`(generate)
- **内容**:generate 前读取旧 topology.json 的 layout,新 payload 沿用;只有节点 id 仍存在的位置被保留(失效 id 丢弃)
- **验收**:改配置重新生成后,仍存在节点保持用户位置,消失节点被清理

#### T5:文件树/输出区点击 topology.json 打开可编辑拓扑
- **文件**:`src/components/layout/ProjectListPanel.tsx`、`src/components/layout/FileTreePanel.tsx`、`src/components/workspace/WorkspaceView.tsx`
- **内容**:
  - 点击 `topology.json`(或 `rack_layout.json`)→ `openTab({ type: 'topology' })` 并选中项目
  - WorkspaceView 的 topology tab 无需改(state 可传 projectName)
  - 区分:模板场景(FileViewerTab isTemplate)不受影响
- **验收**:文件树点击 topology.json 打开拓扑编辑视图(非 JSON 文本)

#### T6:重置布局移除 layout 字段并落盘
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`、`src/stores/design.store.ts`
- **内容**:`handleResetLayout` 清除 localStorage 后,调 store `clearLayout(projectName)` 将 topology.json 的 layout 置 null 并写回
- **验收**:重置后 topology.json 无 layout 数据;重新打开为自动布局

#### T7:旧 schema v1 文件平滑兼容
- **文件**:`src/stores/design.store.ts`(loadSavedTopology)
- **内容**:解析时 `layout` 缺失/结构非法 → 置 null,不抛错;保存时不覆盖 v1 其他字段
- **验收**:含 v1 topology.json 的旧项目正常打开,无报错

#### T8:布局保存状态提示
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`、`src/stores/design.store.ts`
- **内容**:store 记录 `layoutSaved: boolean`;拖拽位置后变未保存,保存后置已保存;工具栏显示状态标识(如 "已保存"/"未保存")
- **验收**:拖拽后出现未保存提示;保存后消失;重新打开项目显示已保存

## v2.8.2 — 拓扑交互增强

**目标**:悬浮信息、链路详情、框选批量操作、节点删除。解决用户反馈第 5 条。

**关联需求**:R3.1 ~ R3.10,问题 F2/F3/U1/U2/B7。依赖 v2.8.1 落盘(R3.10)。

### 任务分解

#### T1:节点 hover 悬浮卡片
- **文件**:`src/components/workspace/tabs/topology/TopologyNodes.tsx`、`TopologyTab.tsx`
- **内容**:
  - ReactFlow 侧:`onNodeMouseEnter`/`onNodeMouseLeave` 记录 hoverNodeId,渲染悬浮卡片(绝对定位,跟随节点中心)
  - 卡片内容:id / 类型 / 组 / Pod / 机柜 / U 位 / 功率 / 连接数(复用现有详情面板字段)
  - 防抖:100ms 延迟显示,避免 2048 节点下频繁切换
- **验收**:悬浮节点 100ms 后显示卡片;移出消失;大图不卡顿

#### T2:链路 hover 悬浮卡片
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:
  - `onEdgeMouseEnter`/`onEdgeMouseLeave` 记录 hoverEdgeId
  - 卡片内容:两端设备 id / 速率 speed / 缆型 cableType / 网络类型 networkType / description
- **验收**:悬浮链路显示完整连接信息

#### T3:链路标签显示(缩放自适应 + 开关)
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:
  - 边增加 `label`(速率,或 `${speed} ${networkType}`)与 `labelStyle`
  - 缩放自适应:`onMove` 时根据 zoom 决定是否显示标签(如 zoom < 0.5 隐藏)
  - 工具栏加"显示链路标签"开关(默认开)
- **验收**:默认显示链路标签;缩放小时自动隐藏;开关可控制

#### T4:框选模式优化
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:
  - 框选模式下 Shift 追加选区(react-flow `selectionMode` 配置或 `onSelectionChange` 合并)
  - Esc 取消选区与框选模式
  - 空格键按住临时平移(panOnDrag 临时生效),松开恢复框选
- **验收**:框选 + Shift 可追加;Esc 取消;空格临时平移流畅

#### T5:Delete 删除选中节点及关联链路
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`、`src/stores/design.store.ts`
- **内容**:
  - keydown Delete 处理(焦点不在输入框时):取 `reactFlow.getNodes().filter(n => n.selected && 非 pod-group)`
  - 删除数据:store 新增 `removeNodes(nodeIds)` —— 从 `topology.nodes` 删除,从 `topology.edges` 删除含这些节点的边
  - 同步:TopologyTab 的 rfNodes/rfEdges 由 computedNodes 重建自动同步
  - 保存联动:删除后 topology.json 需重写(v2.8.1 的 save 链路复用)
- **验收**:Delete 删除节点及关联链路;图即时更新;导出/校验消费 store 数据无误

#### T6:撤销/重做扩展为完整拓扑快照
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:
  - 历史栈从"位置 Map"扩展为 `{ nodes: TopologyNode[]; edges: TopologyEdge[] }` 快照
  - 删除操作入栈;撤销恢复节点与链路;重做重新删除
  - 位置拖拽仍记录(与删除操作共享栈,操作类型标记)
- **验收**:删除后可 Ctrl+Z 恢复;重做可重新删除;位置撤销不受影响

#### T7:链路点击高亮 + 详情
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:`onEdgeClick` 选中边,高亮(加粗/变色),右侧详情面板展示(T2 卡片字段);点击空白取消
- **验收**:点击链路高亮并显示详情;再次点击空白取消

#### T8:框选后对齐操作
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:选中 ≥2 个节点时,工具栏出现对齐按钮(左/右/顶/底对齐,以选区边界为准);对齐后记录历史
- **验收**:框选多个节点可一键对齐;可撤销

#### T9:hover 性能优化
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`、`TopologyNodes.tsx`
- **内容**:hover 状态用单个 state(仅 id),不触发全量重渲染;卡片渲染为独立 ReactNode(不经 ReactFlow 节点 props 传播);`memo` 边界确认
- **验收**:2048 节点悬浮操作帧率稳定(无持续卡顿)

#### T10:编辑状态保存联动(v2.8.1)
- **文件**:`src/components/workspace/tabs/TopologyTab.tsx`
- **内容**:删除/对齐等操作后标记未保存;保存按钮一次落盘(layout + 删除后的 nodes/edges 全部写回 topology.json)
- **验收**:增删/对齐后保存,重开项目状态完整还原
