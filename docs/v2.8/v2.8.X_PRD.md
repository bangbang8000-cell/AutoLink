## 一、背景与定位

### 1.1 产品定位

AutoLink 是 **AI 智算中心网络规划与可视化工具**,卡位"建前规划"环节:

```
NVIDIA Fabric Manager / DCGM  ← 运行时管理(建后)
DCIM 平台                      ← 运维监测(建后)
═══════════════════════════════════════════
AutoLink                       ← 规划设计(建前)  ← 本产品定位
═══════════════════════════════════════════
通用 CAD/Visio                 ← 通用绘图(无领域智能)
```

### 1.2 v2.7.7 基线

v2.7.7 完成了体验与性能系列迭代,核心能力包括:

- 拓扑可视化(react-flow)、Rail-Optimized / Fat-Tree / Scale-Up / UB 拓扑设计
- 机柜 U 位规划、PUE 估算、光模块选型、Web Worker 布局(2048 节点)
- 109+ 设备库、11+ 场景模板、5 语言 i18n、Excel/PDF 导出
- 自动更新、快捷键、撤销/重做、框选模式、POD 折叠、搜索定位

### 1.3 v2.8.X 演进目标

本系列聚焦 **"文件体验 + 拓扑可编辑性"** 四大主题:

## 二、现状评估(基于代码审查,重点)

### 2.1 Excel 加载机制评估

**现状**:存在两套 Excel 查看实现,行为不一致。

| 组件 | 实现 | 切 sheet 行为 |
|------|------|--------------|
| `OutputTab.tsx` | `XLSX.read(base64,{type:'base64'})` 一次解析**全部 sheet** 存入 `Record<string,string[][]>` | 纯 `setActiveSheet`,**零重载** ✅ |
| `FileViewerTab.tsx` | `switchSheet` 每次点击重新 IPC 读文件 → `atob` 逐字节解码 → `XLSX.read` **全量重新解析** → 只转当前 sheet | 每次显示"加载中",**大文件卡顿 1-3s** ❌ |

关键代码:
- [FileViewerTab.tsx](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/tabs/FileViewerTab.tsx#L99-L125) `switchSheet` 重复执行 IPC + 解析
- [FileViewerTab.tsx](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/tabs/FileViewerTab.tsx#L42-L44) `atob` 逐字节 `charCodeAt` 循环(大文件慢)
- [OutputTab.tsx](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/tabs/OutputTab.tsx#L42-L48) 正确范式(一次加载全部缓存)

**影响**:多 sheet 大 Excel 切换页卡顿、重复解析浪费 CPU;两套逻辑维护成本高。

**方案**:
1. 抽取统一 `ExcelTable` 组件(Sheet 标签栏 + 表格渲染),`FileViewerTab` / `OutputTab` 共用
2. `FileViewerTab` 改为一次解析全部 sheet,存入 `dataMap`,切 sheet 纯状态切换
3. 消除 `atob` 逐字节循环,直接 `XLSX.read(base64, { type: 'base64' })`
4. 模块级缓存 `Map<fileKey, workbook>`:重复打开同一文件秒开,不重新解析

### 2.2 图片查看乱码评估

**现状**:全项目 `<img>` 仅 3 处(2 处 logo + OutputTab 预览),拓扑节点为纯 SVG/DOM 无图片。用户反馈的"拓扑图乱码"实为 **PNG 文件被文本查看器按 UTF-8 读取**:

触发链路:
1. 导出拓扑 PNG → 写入项目 `output/组网拓扑图_*.png`(链路本身正确)
2. 侧边栏/文件树点击该文件 → `OutputSection.tsx` / `ProjectListPanel.tsx` 打开 `fileViewer` tab(**只传路径,不传类型**)
3. `FileViewerTab.tsx` [L60-74](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/tabs/FileViewerTab.tsx#L60-L74) 仅识别 xlsx/json,**PNG 走 `project:getFile`(UTF-8 文本读取)**
4. `renderText` 将二进制乱码渲染进 `<pre>` → 用户看到 `�PNG\r\n\x1a...`

次要问题:
- `handlers.ts` [L510](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/electron/ipc/handlers.ts#L503-L511) `listOutputFiles` 返回**大写** `'PNG'`;`OutputTab.tsx` [L51-59](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/workspace/tabs/OutputTab.tsx#L50-L63) 按小写比较,靠 `endsWith('.png')` 兜底,生成 `data:image/PNG;base64,...` 大写 MIME(脆弱),`.PNG` 大写扩展名直接报"不支持"
- **SVG 完全无预览分支**(导出 SVG 后点击同样乱码/源码)

**方案**:
1. `handlers.ts` `listOutputFiles` 返回小写 type(`ext.slice(1).toLowerCase()`)
2. `FileViewerTab` 增加图片分支:png/jpg/jpeg/gif/webp → `getFileBinary` + `data:image/...` 渲染 `<img>`;svg → `data:image/svg+xml;base64,...`
3. `OutputTab` 类型统一 `toLowerCase()`,扩展名小写匹配,补 SVG 分支
4. 全链路按扩展名分发:图片 → 图片预览;Excel → 表格;JSON/INI/TXT → 文本

### 2.3 拓扑持久化与可加载评估

**现状**:
- ✅ `topology.json` 已由 `design.store.ts generate()` 写入**项目根目录**(schema v1:summary/topology/valid/validationIssues/estimation/config_snapshot),已纳入 `project:saveFile` 白名单与 ZIP 导入导出
- ✅ 打开项目时 `loadSavedTopology` 自动读取 `topology.json` 填充 store,拓扑可继续查看
- ❌ **用户调整的节点坐标仅存 localStorage**(`autolink-topology-v4-${project}`),换机器/清缓存即丢失,不随项目导入导出
- ❌ 文件树/输出区点击 `topology.json` 打开的是 **JSON 文本**(fileViewer),不是可编辑拓扑
- ❌ "保存布局"按钮只写 localStorage,无"落盘到项目文件"概念

**方案**:
1. `topology.json` schema 升级 v2:新增 `layout: { version, savedAt, nodePositions: { [id]: {x, y} } }`
2. "保存布局"按钮 → 写回 `topology.json`(localStorage 保留为快速恢复缓存);加载优先级:文件 layout > localStorage > 自动布局
3. 重新生成拓扑时**保留**已保存的 layout,不因重新生成覆盖用户调整
4. 文件树/输出区点击 `topology.json` → 打开 `type:'topology'` 可编辑拓扑 tab(而非文本)
5. "重置布局" → 移除 layout 字段并保存到文件

### 2.4 UI 文案评估(编程 ID 问题)

**现状**:
- `ActivityBar.tsx` [L19](file:///d:/MyCoding/AutoLink/AutoLink_v2.0/src/components/layout/ActivityBar.tsx#L15-L22) 可视化按钮 `labelKey: 'menu.visualization'`,但 **5 种语言 `common.json` 的 `menu` 命名空间均缺该 key**(zh-CN `menu` 仅 projectExplorer/workbench/design/... 无 visualization)→ react-i18next 缺 key 回退显示编程 ID `common:menu.visualization`
- `TopologyTab.tsx` 等存在大量**硬编码中文**(非编程 ID,但与 i18n 体系不一致):"拓扑视图"、"保存布局"、"节点详情"、"适应视图"等
- 需全面审计所有 `t('common:...')` 引用的 key 是否存在于各语言包

**方案**:
1. 5 语言 `common.json` 的 `menu` 命名空间补 `"visualization"`(zh-CN:可视化 / en:Visualization / 其余对应翻译)
2. 新增 i18n key 完整性测试:遍历源码 `t('...')` 引用,断言各语言包均存在(防回归)
3. 梳理 TopologyTab 硬编码文案,纳入 i18n(与现有 key 对齐)

### 2.5 拓扑编辑能力评估

**已具备**:

| 能力 | 说明 |
|------|------|
| 单/多节点拖拽 | react-flow `applyNodeChanges`,拖拽结束记录历史 |
| 框选模式 | `selectionMode` + `selectionOnDrag`(工具栏切换) |
| Shift 多选 | `selectionKeyCode='Shift'`(非框选模式) |
| 撤销/重做 | 位置快照历史栈(Ctrl+Z/Y),仅覆盖位置 |
| 搜索定位 / POD 折叠 / 节点详情面板(点击) | 已有 |
| 保存布局 / 重置布局 | 仅 localStorage |

**缺失(本系列补齐)**:

| 缺口 | 说明 |
|------|------|
| 节点 hover 悬浮信息 | 节点组件无任何 hover 浮层,信息只能点击查看 |
| 链路 hover 悬浮信息 / 链路标签 | 边无 label、无 hover、无点击详情 |
| 布局落盘 | 仅 localStorage,见 2.3 |
| 节点/链路增删 | `nodesConnectable={false}`、无 Delete 处理、无 onConnect |
| 框选批量操作 | 无"全选"、无框选后删除/对齐 |
| 撤销/重做仅位置 | 增删操作无法回退 |

**方案**(v2.8.2):
1. **节点 hover 卡片**:id / 类型 / 组 / Pod / 机柜 / U 位 / 功率 / 连接数,跟随鼠标
2. **链路 hover 卡片**:两端设备 / 速率 / 缆型 / 网络类型 / 端口;链路标签默认显示(速率+网络类型),支持按缩放级别/开关控制稠密显示
3. **框选优化**:框选模式下 Shift 追加选区、Esc 取消;空格键临时切换平移/框选
4. **删除功能**:Delete 键删除选中节点及其关联链路,同步更新 store 拓扑数据(edges 清理 + connectionCount 重算),撤销/重做扩展为完整拓扑快照
5. **性能**:hover 信息防抖渲染,2048 节点避免全量重渲染(仅更新单个目标)
