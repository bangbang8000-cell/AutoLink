# AutoLink V2.1 开发计划

## 总体策略

**分阶段交付，每阶段产出可运行版本。** 核心思路：先数据模型、再UI交互、最后打磨发布。

**重大架构变更：**
- `network_config.ini` → `project_config.json`（引用设备库的 project config）
- `NetworkObject` 硬编码 → `DeviceProfile` 参数驱动
- 新增**全局设备类型库**（40 款内置设备，独立于项目/模板，支持手工添加/编辑/批量导入/导出）
- 项目通过 `library_id + overrides` 引用设备库，避免参数冗余

**向后兼容承诺：** V2.0 项目自动迁移，用户无感知升级。

## 风险与建议

### 风险
1. **40款设备 JSON 工作量**：每款设备需要调研真实参数并录入，特别是接口模型（服务器）和端口配置（交换机），建议优先完成常用设备，其余用通用型号占位
2. **设备库引用解析链路**：project → device_refs → 设备库 JSON → Python DeviceProfile → NetworkObject 这条链路的每一环都需要正确处理 overrides
3. **Python 引擎大改**：designer.py 改动量大，需仔细回归测试
4. **拓扑编辑**：ECharts draggable 模式下的坐标保存/恢复需要处理坐标系转换

### 核心建议
1. **Phase A 是重中之重**：40款设备 JSON + Python 设备库加载器是整个 V2.1 的基础
2. **设备库独立测试**：设备库是独立模块，可以在 UI 之前先通过 Python 单元测试验证
3. **overrides 机制要严格控制**：只允许覆盖合理字段（功率/U高/端口前缀等），核心型号信息不可覆盖
4. **保持设备库 JSON 格式一致性**：每款设备 JSON 必须通过 schema 校验，确保 Python 和 TypeScript 双端解析一致
