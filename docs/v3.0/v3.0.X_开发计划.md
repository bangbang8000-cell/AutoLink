## 二、架构改造总纲（3.0 系列核心工程）

### 2.1 拓扑引擎插件化 + 正交模型（PRD R0.2/R0.4）

**目标**：designer 重构为"网络域（组网形态）× GPU 池/集群（正交）"双轴驱动。

| 步骤 | 内容 | 关键文件 |
|------|------|----------|
| 1 | 抽象 `NetworkDomain`（type/planes/tiers/protocol/speed/ports_per_server/leaf_count）+ `Cluster`（cluster_id/role: P/D/network_mode/gpu_pools/scale），designer 对象存储泛化为 `self.domains[]`/`self.clusters[]`（保留旧属性别名兼容） | `backend/designer.py` L43-52、L551-709、L1037-1053 |
| 2 | `network_plugin.py` 接线：engine 按 `network_mode` 查插件（param/storage/biz/oob/dual_plane/zcube/huawei_supernode/combined_eth/scale_up/fat_tree/rail）；插件输出转 designer 对象/连接 | `backend/network_plugin.py`、`backend/engine.py` |
| 3 | 统一访问器 `all_devices()/all_switch_groups()`，exporter/validation/engine 全部改走访问器 | `backend/exporter.py`、`backend/engine.py` |
| 4 | 旧配置兼容：无 `clusters`/`network_mode` 时走默认四网组装（结果与 2.9.9 一致） | `backend/designer.py` |

**验证**：16 个内置模板 design 结果与 2.9.9 全量 diff 为空（golden 基线先行）。

### 2.4 Python 持久 Agent 进程（PRD R0.5）

| 步骤 | 内容 | 关键文件 |
|------|------|----------|
| 1 | `engine.py` 逐行读 stdin（循环）+ NDJSON 输出（`{type:'result'|'event'|'error', requestId}`）逐行 flush | `backend/engine.py` main() |
| 2 | `python-agent.service.ts`：单例长驻进程、请求队列（并发≥3）、requestId 分发、空闲超时、异常自动重启（计数+退避） | `electron/services/python.service.ts`（重构） |
| 3 | 兼容层保留 `call(action, params, timeout)` 旧签名，现有 IPC 零改动 | `electron/services/python.service.ts` |
| 4 | 流式事件 `webContents.send('ai:stream', chunk)` + `{type:'event'}` 行透传 | `electron/preload.ts`、`handlers.ts` |

**风险点**：持久进程内存泄漏/状态污染 → 重大 action 后状态快照校验，异常自动重启重试一次。
