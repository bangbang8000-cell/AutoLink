## 一、评估说明

### 1.1 评估范围与方法

| 项 | 说明 |
|----|------|
| 评估对象 | AutoLink v2.9.9 全量工程（backend 16 模块 / electron 5+ 文件 / src 前端 / template 16 模板 + 118 设备 / CI 双工作流） |
| 评估方法 | 架构走查 + 全量代码阅读 + 测试与 CI 审查 + 用户旅程推演 + 技术债盘点 |
| 评估视角 | 软件架构师、软件设计师、程序员、测试员、运维、美工、用户（7 角色） |
| 产出 | 能力全景、分角色评估、问题分级清单、风险矩阵、3.X 战略启示 |

### 1.2 结论摘要（一句话）

**v2.9.9 是一套"专业、完整、可靠"的 2.9 代桌面工具：单机单用户、功能面覆盖广、质量门禁扎实；但它的三大天花板——四网模型硬编码（难以承载新组网）、Python 进程模型无状态（难以承载 AI 对话）、完全离线无账号无云端（难以承载协作与分发）——正是 3.X 系列必须跨越的三座山。**

## 三、软件架构师视角评估

### 3.1 总体架构评价

```
渲染层(React/Zustand)  →  preload(contextBridge)  →  主进程 IPC(handlers.ts)
                                                          ↓ pythonService.call(action)
                                                    Python 子进程 engine.py
                                              @register_action 装饰器注册表 → designer/validation/exporter
```

架构分层清晰、职责单一、安全边界明确（渲染层 0 网络、0 Node 权限），是 2.X 系列最核心的资产。但存在 8 项结构性技术债（C1~C8），直接影响 3.X 愿景落地。

### 3.2 架构亮点（保留资产）

1. **Action 注册表模式**（`engine.py` `@register_action`）：新增后端能力只需注册一个 handler，主进程协议零侵入——AIHUB 新增 `chat/generate/agent` 等 action 可直接复用该模式。
2. **ProjectConfig 单一事实源**：`project_config.json` 是向导/模板/设计/校验/迁移的唯一数据契约，前端 `wizard.store.config` 与后端 `validate_config` 双向对齐——AI 生成项目/模板只需构造 ProjectConfig。
3. **领域 IPC 分层**：project/template/design/device-library/render 五个域互不越界，`wrapHandler` 统一异常，天然适合新增 `auth:*`/`cloud:*`/`ai:*` 域。
4. **事件推送先例**：`render:progress`/`log:output` 已实现"主→渲染逐条推送 + 取消订阅"，是 AIHUB 流式对话的现成骨架。
5. **Store 跨层编排**：`project.store.selectProject` 联动 design/rack/workspace 多 store，是 AI 工具调用（tool calling）编排现有能力的骨架。

### 3.3 架构问题与技术债

| 编号 | 问题 | 影响 | 位置 |
|------|------|------|------|
| C1 | **四网模型硬编码**：`networks` 四布尔、designer 对象存储/层次/连线、validation 速率表、exporter sheet、rack 网段推断 5 处耦合 | 双平面/Zcube/新平面必须大改，违反开闭原则 | `project_config.py`、`designer.py`、`validation.py`、`exporter.py`、`rack_allocation.py` |
| C2 | **插件层未接线**：`network_plugin.py` 已定义 `NetworkPlugin` 接口但无生产调用方 | 插件化组网路线名存实亡，新组网只能硬编码 | `network_plugin.py`、`engine.py` |
| C3 | **UB 模块孤立**：`ub_topology.py` 全量算法无生产调用 | 昇腾/Zcube 场景资产闲置 | `ub_topology.py` |
| C4 | **Python 进程模型无状态**：每次调用 spawn 新进程、60s 硬超时、stdout 全量累积后解析 | 无法承载 AIHUB 长会话/流式/可中断 | `python.service.ts`、`engine.py` |
| C5 | **配置 schema 无版本演进**：`meta.version=1` 无独立 schema_version、REQUIRED_KEYS 硬校验 | 新增字段即破坏旧模板，3.X 演进无安全路径 | `project_config.py` |
| C6 | **交换机端口模型固化"半口下联"** | 16 Leaf、非对称收敛、双平面特殊收敛无法表达 | `models.py` L62-81、`topology.py` L139 |
| C7 | **单一 GPU 型号**：`num_gpu_servers` 单整数 + `device_refs.gpu_server` 单档案 | GPU 异构（多池混布/PD 分离）完全无法表达 | `designer.py` L654-666、`project_config.py` |
| C8 | **无持久化服务层与网络层**：主进程仅 GitHub 更新一处网络、无数据库、无认证 | 登录/云端/同步/分享从零建设 | 全局 |

### 3.4 架构建议（对应 3.X）

1. 将 C1/C2/C3 合并解决：**拓扑引擎插件化接线**——designer 由"四网硬编码"重构为"网络域/平面列表驱动"，新增组网=新增插件，engine 按 `network_mode` 分派。
2. 将 C4 重构为 **Python 持久 Agent 进程**：NDJSON 行级协议、按 requestId 多路复用、空闲超时替代整体超时、流式输出——AIHUB 与容量规划共用。
3. 将 C5 建立 **schema 版本化 + 迁移链**：`schema_version` + 逐版本 migration，新字段全部可选，兼容 2.9.9 全部旧模板。
4. 将 C6/C7 数据模型升级：**端口容量显式化（downlink/uplink 解耦）+ GPU 池化（gpu_pools）**。
5. C8 按"主进程网络层、渲染层仍 0 网络"红线扩展：`auth:*`（OAuth 授权码）+ `cloud:*`（gita 适配器）+ `safeStorage` 凭据。

## 四、软件设计师视角评估

### 4.1 交互设计评价

整体为 VS Code 式 IDE 三栏布局（活动栏/侧栏/工作区 Tab/底部面板），信息密度高、专业感强，符合工程师工具定位。核心流程（模板→项目→渲染→导出）被向导、工作台、模板中心等拆成清晰入口。

### 4.2 设计亮点

1. 5 步创建向导 + 协议联动智能默认选型（`getDefaultRefs`）——显著降低入门门槛。
2. 模板中心"规模摘要 + 预览方案 + 健康检查"三件套——模板选择有据可依。
3. 机柜 4 视图（U 位/热力图/多柜对比/等轴侧）覆盖不同作业场景。
4. 统一 token 体系（`app/edge/primary/success/error`）+ 深浅双主题 + `motion-off` 无障碍。

### 4.3 设计问题

| 编号 | 问题 | 影响 |
|------|------|------|
| D1 | 向导仍要求用户填写 8+ 网络参数，AI 缺失时门槛高 | 新手上手困难 |
| D2 | 多组件硬编码中文（WizardStepDevices、DeviceLibraryTab 等），i18n 测试未覆盖 | 5 语言体验断裂 |
| D3 | 表单控件样式多处内联重复（input/toggle 未收敛至 `ui/` 组件库） | 维护成本、风格漂移 |
| D4 | Topology3D/DataCenter 平面图停留在 PoC 观感 | 演示/交付说服力弱 |
| D5 | 无"需求→方案"入口，用户必须自己填参 | 从需求到设计割裂 |
| D6 | 无协作/分享入口（单机单用户心智） | 无法承载团队工作流 |

### 4.4 设计建议

1. **AIHUB 双轨制**：对话生成（AI 代理）+ 向导确认（人类接管），复用同一 ProjectConfig 契约，先 AI 填充再人工微调。
2. 将 `getDefaultRefs`/设备分组抽为共享模块，向导、模板编辑、AI 三处共用，消除 D3/D1 重复。
3. 新组网（双平面/Zcube）需设计新的拓扑可视语言（平面切换、cube 域分组），而非复用四网配色硬套。
4. 补全 i18n 覆盖（把硬编码文案迁入命名空间），i18n 测试已能自动强制 5 语言补齐。

## 五、程序员视角评估

### 5.1 代码质量评价

TypeScript strict + ESLint 0 error、Python 模块职责清晰、测试先行（TDD 痕迹明显）、命名规范统一。整体处于"企业内部高质量工具"水准。

### 5.2 亮点

1. `wrapHandler` 统一异常 + 超时清理（SIGTERM→SIGKILL）链路完整。
2. i18n key 完整性三层测试（命名空间/展平 key/插值变量）——极佳实践。
3. 模板 ZIP 导入"强校验 + 失败回滚删除"——防御式编程到位。
4. 导出 excel 分片解析（200 行让出主线程）+ 缓存，大文件体验良好。

### 5.3 代码问题

| 编号 | 问题 | 影响 |
|------|------|------|
| P1 | exporter 聚合 `param_leaves+...+biz_agg` 硬编码 11 类列表（多处重复） | 新组网导出静默缺项 |
| P2 | `getDefaultRefs` 设备选型映射只存在于 WizardStepDevices 组件内 | AI 无法复用，规则双写 |
| P3 | `requirements.txt` 混入测试依赖（pytest/pytest-cov）进运行时 | 分发不友好 |
| P4 | INI/JSON 双格式并存双维护（migration/反向序列化），字段增改需两处同步 | 易漏同步 |
| P5 | `pythonService.call` 无 requestId/会话概念，无法取消、无法流式 | 阻塞 AIHUB |
| P6 | 设备库自定义设备写入 `resourcesPath`（打包后只读语义），handlers 未限制 | 潜在不一致 |
| P7 | `project:createWithConfig`/`device-library:save` 等 payload 无运行时 schema 校验（仅编译期类型） | 安全薄弱点 |

### 5.4 代码建议

1. 为 designer 提供统一访问器（`all_switch_groups()`/`all_devices()`），exporter/engine/validation 全部改走访问器，消除 P1。
2. 抽取 `src/utils/device-defaults.ts` 共享选型规则，消除 P2。
3. 拆分 `requirements.txt`（运行时）/`requirements-dev.txt`（测试），消除 P3。
4. 新配置一律 JSON 优先、INI 仅保留导入兼容，逐步弱化 P4。
5. 新 IPC payload 引入运行时校验（zod），先覆盖 `auth:*`/`cloud:*`/`ai:*` 新域，消除 P7。

### 6.1 测试资产盘点

| 资产 | 数量 | 覆盖 |
|------|------|------|
| vitest（前端） | 354 passed / 19 文件 | store、组件、i18n key 完整性、布局算法 |
| pytest（后端） | 560 passed / 14 文件 | 引擎、选型、机柜装箱、迁移、导出、PUE、校验规则 |
| 模板验证 | 16/16 | 内置模板 schema + 设备引用 |
| i18n 完整性 | 3 层 | 命名空间/key/插值 |

### 6.2 覆盖亮点

- 迁移测试（test_migration_full）、Scale-Up 与插件测试（test_scaleup_and_plugin）覆盖了最复杂的后端路径。
- i18n 完整性测试是全仓库最严苛的质量红线之一。

### 6.3 测试缺口

| 编号 | 缺口 | 风险 |
|------|------|------|
| Q1 | **CI 不跑 vitest、不跑 electron 主进程构建**（ci.yml 仅 typecheck/lint/build:renderer/pytest） | 前端回归靠人工，3.X 高节奏下必漏 |
| Q2 | 无 E2E（Electron 全链路冒烟） | 主进程/渲染层集成缺陷只能在手测发现 |
| Q3 | 拓扑算法无 golden file 测试 | 新组网（双平面/Zcube/16Leaf）公式回归无锚点 |
| Q4 | 无性能基准（大集群 2048 GPU 渲染/设计耗时） | 3.X"更高效"无量化依据 |
| Q5 | 无故障注入（Python 崩溃/超时/损坏文件） | 异常路径无回归保护 |
| Q6 | 机柜装箱算法（NP-hard 类）无随机性质测试 | 边界场景可能遗漏 |

### 6.4 测试建议

1. **CI 全量门禁**：ci.yml 纳入 `npm test`（vitest）+ `tsc -p tsconfig.electron.json`（主进程构建）+ `python scripts/validate_templates.py`。
2. 引入 **Playwright + Electron** E2E 冒烟（登录→建项目→渲染→导出）。
3. 为 3.X 每个新拓扑算法配 golden file（输入 config → 断言 node/edge 快照）。
4. 建立性能基准脚本（pytest-benchmark / vitest bench），纳入 3.3 性能版本。

## 七、运维视角评估

### 7.1 发布链路评价

CI/CD 闭环完整（tag → 三平台打包 → GitHub Releases → electron-updater 自动更新 + 国内 fallback），但存在影响 3.X 规模化分发的短板。

### 7.2 亮点

1. 自动更新双通道（electron-updater + `net` 模块 fallback，重定向处理完善）——国内网络友好。
2. NSIS 安装器（可改目录/快捷方式）符合企业分发习惯。
3. `workflow_dispatch` 手动触发 + 模板验证入 CI，发布可控。

### 7.3 运维问题

| 编号 | 问题 | 影响 |
|------|------|------|
| O1 | **macOS 未签名**（`CSC_IDENTITY_AUTO_DISCOVERY:false`） | mac 用户 Gatekeeper 拦截，企业部署受阻 |
| O2 | **Python 运行时依赖用户机器**（spawn 'python'，requirements 由用户装） | 部署地狱；3.X 加 LLM 依赖后不可接受 |
| O3 | **单一 latest 更新通道**，`isVersionNewer` 拒绝预发布版本号 | 2.9/3.0 并行维护无法分通道 |
| O4 | 无崩溃上报/遥测 | 线上缺陷不可见，"更稳定"无数据 |
| O5 | 用户数据（workspace/user-templates）无备份、无同步 | 数据丢失不可恢复 |
| O6 | 无升级数据迁移入口（跨 major 升级旧项目配置） | 3.0 兼容性压力大 |

### 7.4 运维建议

1. 3.0 起 **PyInstaller 打包 Python 后端**（或内嵌运行时），用户免装 Python；测试依赖移出运行时包。
2. 更新服务改为 **多通道**（`latest-v3.yml`/`latest-v2.yml`），版本比较升级为 semver 化。
3. 引入崩溃上报（Sentry / 自建），脱敏后上传。
4. 3.X 云端（gita）同时解决 O5 数据备份 + O6 跨版本迁移（云端存 schema 版本，本地升级时拉取迁移）。

3. 3D 拓扑升级（instancing + 材质 + 交互动效），机柜等轴视图与机房平面图打磨到交付级。
4. PDF 报告重设计（品牌页眉/图表配色/排版密度）。

| 国产化项目组 | 昇腾/海光/寒武纪兼容 | ★★★☆☆ |

### 9.2 核心旅程评价

模板→项目→渲染→导出主链路顺畅；模板中心/预览/健康检查显著优于 2.6 代。但"从组网需求到配置"仍依赖人工填参，是最大的效率断点。

### 9.3 用户痛点

| 编号 | 痛点 | 用户原声（推断） |
|------|------|------|
| U1 | 8+ 参数手填，不懂收敛比/Scale-Up 域就卡住 | "我不知道该填什么" |
| U2 | 新组网（双平面/Zcube/800G IB/16 Leaf）无法表达 | "客户要双平面，工具不支持" |
| U3 | 异构 GPU（H100+B300 混布、PD 分离）做不了 | "我们机房就是异构的" |
| U4 | 数据只在本机，换机器/换人即断档 | "项目拷来拷去，版本乱" |
| U5 | 无法与同事分享模板/项目 | "我们团队没有协作入口" |
| U6 | 出错后不知道去哪求助 | "要是有个 AI 帮我看就好了" |

### 9.4 用户建议（对应 3.X）

1. **AIHUB 对话**：直接说"我要 1024 台 B300 双平面 800G IB，收敛比尽量低"→ 自动出方案。直击 U1/U2/U3。
2. **示例文件导入生成**：粘贴拓扑需求文档/示例 Excel → 生成项目/模板。直击 U1。
3. **云端 gita + 登录**：项目/模板公共库、私有库、跨机同步。直击 U4/U5。
4. **分享链接**：一键把方案/模板分享给同事。直击 U5。
5. **智能助手兜底**：校验错误时 AI 给出修复建议并可直接执行。直击 U6。
