# AutoLink v2.5 产品需求文档(PRD)

> **版本**:v2.5.0(定稿)
> **日期**:2026-07-30
> **作者**:AutoLink Team
> **状态**:待评审 → 评审通过后进入开发
> **范围**:Logo 定稿 + 关于弹窗改版 + 新建项目入口补全 + 4 项 P0 缺陷修复
> **变更摘要**(相比 v2.4.7):R1 Logo 定稿(方案一,带穿出横线的 A 形);R2 关于弹窗底部状态栏;R3 新建项目入口(菜单+按钮);R4-R7 紧急缺陷修复

---

## 1. 背景

v2.4.7 完成了 Phase K4 拓扑交互增强(搜索定位、框选、撤销重做、POD 折叠)。在产品体检中发现以下问题需在 v2.5 解决:

1. **Logo 识别度不足**:原 Logo 节点偏小、A 字轮廓模糊,被感知为"倒 V"
2. **关于弹窗信息陈旧**:软件栈版本硬编码、无检查更新入口、与 Header 更新弹窗割裂
3. **新建项目入口失效**:菜单 Ctrl+N / 欢迎页按钮均无响应(`showCreateProjectWizard` 状态无人消费)
4. **多项 P0 缺陷**:项目删除按 index 误删风险、打包后模板写入失败、更新监听器泄漏

v2.5 聚焦"品牌识别 + 入口可用 + 紧急修复",不引入新业务功能,为 v2.6 的从模板创建、回收站等增强功能打基础。

## 3. 详细需求

### R1:Logo 定稿与多尺寸输出

#### 3.1.1 用户故事
作为用户,我希望 AutoLink 的 Logo 在任务栏、安装包、关于弹窗、启动屏等各处都清晰可辨,能一眼识别"A"字形与网络拓扑寓意。

#### 3.1.2 设计规范(定稿)

**方案**:方案一(锐角 A),已选定并完成像素级验证。

| 元素 | 规格 |
|---|---|
| 画布 | 512×512,viewBox `0 0 512 512` |
| 背景 | 蓝色圆角正方形,`x=16 y=16 w=480 h=480 rx=100`,渐变 `#0EA5E9`→`#2563EB`(对角,`userSpaceOnUse`) |
| 倒 V 两条腿 | 白色粗笔画,stroke-width=40,`M 160 392 L 256 120 L 352 392`,stroke-linecap/join=round,带辉光 filter(stdDeviation=3) |
| 横线 | 白色粗笔画,stroke-width=40,`M 112 260 L 400 260`,stroke-linecap=round,**无 filter**(避免被腿辉光遮挡) |
| 5 个端点圆圈 | 全部 r=18,纯白填充,无描边。位置:顶点(256,120)、左底角(160,392)、右底角(352,392)、横线左端(112,260)、横线右端(400,260) |
| 横线长度 | 288px(400-112),与单条腿长度(√(96²+272²)≈288.4)等长 |
| 横线位置 | y=260(画布 60% 处),此处腿宽约 88px,横线穿出腿外侧约 75px,A 字完整 |
| 辉光策略 | 仅腿带 `glowLeg` filter(stdDeviation=3);横线无 filter。**硬约束:横线不可加任何 filter,否则被腿辉光在两腿间隙遮挡而消失**(已两次验证) |
| 渐变模式 | 所有 `linearGradient` 必须使用 `gradientUnits="userSpaceOnUse"` + 绝对坐标。**硬约束:不可用默认 `objectBoundingBox`,否则水平线渐变失效**(已验证) |
| 已删除元素 | 四角点缀圆点(opacity 0.18,肉眼不可见,属噪点) |

**主矢量源文件**:`build/logo.svg`(已定稿)

#### 3.1.3 多尺寸输出物

| 文件 | 尺寸 | 用途 | 生成方式 |
|---|---|---|---|
| `build/logo.svg` | 512×512 | 主矢量源 | 已就绪 |
| `build/icon.png` | 1024×1024 | electron-builder 主图标 | sharp 转换 |
| `build/icon.ico` | 16/32/48/64/128/256 | Windows 任务栏/安装包 | **必须合法 ICO 格式(文件头 `00 00 01 00`),不可 PNG 改名**(项目记忆约束) |
| `build/icon.icns` | 多尺寸 | macOS | electron-builder 生成 |
| `public/icons/logo.svg` | 512×512 | 运行时引用(关于弹窗等) | 已就绪 |
| `public/icons/icon.png` | 512×512 | 运行时引用 | sharp 转换 |
| `public/splash.html` 内嵌 SVG | — | 启动屏 | 同步替换内嵌 SVG(描边可适当加粗适配透明背景) |

#### 3.1.4 验收条件
1. `build/logo.svg`、`public/icons/logo.svg` 内容与规范一致
2. `build/icon.png`(1024×1024)、`build/icon.ico`(多尺寸合法 ICO)生成成功
3. Windows 安装包、macOS DMG、Linux AppImage 图标均为新 Logo
4. 应用启动后:任务栏图标、标题栏、关于弹窗、欢迎页均为新 Logo
5. 16px 尺寸下 A 字轮廓仍可辨(5 节点中至少 3 个可见)
6. 浅色/深色背景下均清晰(蓝底白主体为主用法)

### R4:修复新建项目向导弹出失效

#### 3.4.1 缺陷描述
`App.tsx` 中 `showCreateProjectWizard` 状态已定义但**无消费者**,菜单 Ctrl+N 与欢迎页按钮调用 `setShowCreateProjectWizard(true)` 后无 Modal 渲染,点击无响应。

#### 3.4.2 修复方案
在 `App.tsx` 中根据 `showCreateProjectWizard` 状态渲染 `CreateProjectWizardModal`:
```tsx
{showCreateProjectWizard && (
  <CreateProjectWizardModal
    onClose={() => setShowCreateProjectWizard(false)}
    onCreated={(project) => { /* 打开项目 */ }}
  />
)}
```

#### 3.4.3 验收条件
1. 所有入口(R3 的三处)点击后向导弹出
2. 向导 5 步流程完整可用
3. 创建后项目自动打开

### R5:修复项目删除误删风险(index→name)

#### 3.5.1 缺陷描述
`project:delete` IPC 当前按 `index` 删除项目。删除操作期间列表可能重排序,导致 index 偏移,**删除错误的项目**。

#### 3.5.2 修复方案
- IPC 签名:`project:delete` 参数从 `index: number` 改为 `name: string`
- 后端 `handlers.ts`:按 `name` 查找并删除
- 前端 `project.store.ts`:调用方传 `name` 而非 `index`
- 确认弹窗 `ConfirmDeleteDialog` 显示项目名而非 index

#### 3.5.3 验收条件
1. 删除操作按项目名定位,不受列表顺序影响
2. 连续删除多个项目不会误删
3. 删除不存在的项目名返回明确错误

### R6:修复打包后模板写入失败

#### 3.6.1 缺陷描述
`getTemplatePath()` 统一返回 `resourcesPath/template`,打包后该目录只读。用户执行"项目另存为模板"或"编辑模板"时写入失败。

#### 3.6.2 修复方案
拆分模板路径:
- **内置模板**(只读):`resourcesPath/template`
- **用户模板**(读写):`userData/user-templates/`

IPC 调整:
- `template:list`:合并返回内置 + 用户模板(标记 `isBuiltIn`)
- `template:create` / `template:update` / `template:delete`:仅操作 `userData/user-templates/`
- 内置模板不可删除/编辑(UI 灰显)

#### 3.6.3 验收条件
1. 打包环境下"项目另存为模板"成功
2. 内置模板仍可查看,但删除/编辑按钮灰显
3. 用户模板可编辑/删除
4. 模板列表合并显示两类,内置模板有标记

### R7:修复更新监听器泄漏

#### 3.7.1 缺陷描述
`update.service.ts` 的 `downloadUpdate()` 每次调用都注册新的 `download-progress`/`update-downloaded`/`error` 监听器,不清理。多次下载后监听器累积,导致回调重复执行、内存泄漏。

#### 3.7.2 修复方案
```typescript
downloadUpdate(): void {
  const updater = this.getAutoUpdater();
  // 注册前先清理,避免累积
  updater.removeAllListeners('download-progress');
  updater.removeAllListeners('update-downloaded');
  updater.removeAllListeners('error');
  updater.on('download-progress', p => mainWindow?.webContents.send('update:downloadProgress', {...}));
  // ...
}
```

#### 3.7.3 验收条件
1. 连续触发下载 5 次,监听器数量不累积(可用 `updater.listenerCount` 验证)
2. 下载进度回调仅触发一次/事件
3. 无内存增长异常
