## 1. 快速开始

### 1.1 首次启动

首次启动 AIDC AutoLink 时，系统会：

- 展示 **3 步引导**（创建项目 → 配置设计 → 可视化与交付），看过一次不再弹出
- 自动创建 3 个示例项目，方便快速体验：
  - **示例-H100-100台**：100 台 H100 GPU（入门示例）
  - **示例-H100-128台**：128 台 H100 GPU，4 组 Rail（Rail-Optimized 示例）
  - **示例-L20-推理-64**：64 台 L20 推理集群（推理场景示例）
- 内置 **16 套场景模板** 与 **118 款设备库**

### 1.2 界面布局

AIDC AutoLink 采用经典 IDE 风格布局：

| 区域 | 说明 |
|------|------|
| **顶部菜单栏** | 文件 / 编辑 / 视图 / 项目 / 帮助 |
| **左侧活动栏** | 项目浏览器 / 拓扑设计 / 机柜规划 / 可视化 / 设备库 / 设置 |
| **左侧文件浏览器** | 项目列表、输出文件、模板中心 |
| **中间工作区** | 标签页形式展示各功能面板（Tab 按项目隔离） |
| **右侧面板** | 日志输出 / 属性面板 |
| **底部状态栏** | 当前项目、状态信息 |

### 1.3 创建第一个项目

1. 点击左侧活动栏的「项目浏览器」图标
2. 点击顶部「+」按钮，或选择「从模板创建」
3. 在项目向导中填写（**分步校验**，无法继续时按钮下方会明确提示原因）：
   - **项目名称**：如 `我的第一个项目`（必填，≤50 字符，不能重名）
   - **GPU 服务器型号**：选择 H100 / B200 / 昇腾 / MLU590 等
   - **GPU 服务器数量**：如 100 台（上限 2048）
   - **参数网络协议**：IB / RoCE / **UEC**
   - **Scale-Up 配置**（可选）：protocol / num_gpus / domain_size / bandwidth
   - **存储/业务/带外网络**：按需开关
4. 点击「下一步」完成设备选型
5. 点击「完成」创建项目

## 2. 项目管理

### 2.1 项目列表

在左侧文件浏览器的「全部项目」区域可以看到所有项目。右键菜单支持：

- **设为当前项目** / **在文件管理器中打开** / **复制项目** / **重命名**
- **导出为 ZIP**：打包项目（含拓扑与机柜数据）为压缩文件
- **转为模板**：将项目保存为可复用模板
- **收藏置顶** / **删除项目**（不可恢复）

### 2.2 项目结构

```
项目名称/
├── project_config.json    # 项目配置（V2.1+ 格式，优先读取）
├── network_config.ini     # 网络配置（V2.0 格式，向后兼容）
├── project.json           # 项目元数据
├── topology.json          # 拓扑数据（含布局，自动保存）
├── rack_layout.json       # 机柜布局数据（500ms 防抖自动保存）
└── output/                # 输出文件目录
    ├── connection_table.xlsx
    ├── rack_table.xlsx
    └── topology.png
```

**数据持久化**：拓扑与机柜数据按项目保存，切换项目自动加载对应数据，重启后恢复；项目导出/导入 ZIP 完整保留。

**配置优先级**：`project_config.json` 与 `network_config.ini` 同时存在时，以 JSON 为准。

### 2.3 项目文件浏览

- **智能分组**（默认）：输入配置 / 输出文件 / 拓扑数据 / 其他文件，输出批次按时间倒序
- **真实分组**：按文件系统目录结构展示
- Excel / JSON / 图片 / 配置文件均可点击预览（Excel 一次性加载全部 Sheet，切换零重载）

### 2.4 模板中心

- 内置 16 套场景模板（H100 / L20 / NVL72 / SuperPOD / 昇腾 / 液冷 / UALink / CloudMatrix / UEC 等）
- 用户模板：通过「项目转模板」创建
- 支持模板编辑、导入、导出、删除、预览、健康检查
- 模板列表支持按场景/标签/名称搜索，并可筛选内置/用户模板

### 2.5 从模板创建项目

1. 模板列表中右键目标模板 → 「基于此模板创建项目」，或模板预览弹窗中点击「基于此模板创建项目」
2. 创建向导自动预填模板的规模 / 网络 / 选型 / 机柜配置
3. 按需调整（向导第 1 步可「重置为默认」清空模板预填）→ 完成创建
4. 创建后 DesignTab 选型/机柜完整继承模板配置

> 模板不存在或配置损坏时创建会明确报错，不会残留空项目。

### 2.6 沉淀与编辑模板

**沉淀（另存为模板）**：项目列表中右键项目 → 「转为模板」，填写名称/描述/场景/标签后保存到用户模板目录。

**可视化编辑**：右键用户模板 → 「编辑模板」，打开表单化编辑器：

- **基本信息**：名称 / 描述 / 场景 / 标签
- **规模设置**：GPU / 全闪 / 混闪 / 通算数量、网卡/交换机口数、速率、协议（IB/RoCE/UEC）、下行模式与 4 网下行数
- **网络类型**：参数网 / 存储网 / 业务网 / OOB 开关
- **选型设置**：按网络分组复用设备库选择器
- **机柜设置**：42U/49U、功率预设、散热方式、GPU 独占、命名前缀
- **JSON 原文**：高级用户可手动编辑 `project_config.json`（保存前校验，后端校验失败会提示具体错误）

保存时自动同步生成 `network_config.ini`（JSON + INI 双文件一致）。内置模板为只读，不可编辑（可先导出再导入为用户模板）。

### 2.7 模板预览

右键模板 → 「预览方案」即时查看设计结果（临时生成，不落盘）：

- 校验状态横幅（通过 / 未通过 + 错误数）
- 统计卡片：服务器 / 交换机 / 机柜 / 总功率 / 协议 / 收敛比
- 校验错误列表（最多 8 条）
- 快捷入口：「去编辑」/「基于此模板创建项目」

缺少 `project_config.json` 的旧模板预览时给出明确提示，不静默失败。

### 2.8 模板分享（导入/导出）

**导出模板为 ZIP**：右键模板 → 「导出为 ZIP...」，生成包含以下文件的压缩包：

| 文件 | 必选 | 说明 |
|------|------|------|
| `template.json` | 是 | 模板元数据（名称/描述/场景/标签/创建时间） |
| `project_config.json` | 推荐 | V2.1 项目配置（规模/网络/选型/机柜，JSON 与 INI 二选一或并存） |
| `network_config.ini` | 推荐 | V2.0 配置（旧格式，兼容历史工具） |

**导入模板**：工具栏「导入模板 ZIP」→ 选择压缩包，导入后自动写入用户模板目录。

**导入强校验**（V2.9.8）：
- ZIP 含 `project_config.json` → 自动执行配置校验（`validate_config`），**校验失败则拒绝导入并回滚**
- 仅含 `network_config.ini` → 自动调用 Python 迁移生成 `project_config.json` 后导入
- 两者皆无 → 明确拒绝（不是有效模板包）

导入成功后，模板列表自动刷新；可在「模板健康检查」中确认模板可用性。

### 2.9 模板健康检查

工具栏 ❤ 图标（模板健康检查）扫描全部内置 + 用户模板，定位损坏模板：

- 缺少 `project_config.json`（仅含 INI）
- `project_config.json` 解析失败
- 配置语义校验失败
- 选型引用失效（`device_refs` 引用的设备不在设备库中）

结果弹窗展示健康/异常汇总与逐项错误详情，便于定位并修复损坏模板。

## 4. Scale-Up 双栈规划

> v2.9 起 Scale-Up（GPU 卡间互联）与 Scale-Out（服务器间网络）双栈一体化规划正式转正。

### 4.1 启用 Scale-Up

在项目配置的 `scale_up` 段（JSON）或 `[scale_up]` section（INI）中配置：

```json
{
  "scale_up": {
    "protocol": "UALink",
    "num_gpus": 1024,
    "gpus_per_node": 8,
    "domain_size": 1024,
    "bandwidth": 200
  }
}
```

- `protocol`：NVLink / UALink / UB
- `num_gpus`：Scale-Up GPU 总数
- `domain_size`：单域规模（0 = 按协议默认）
- `bandwidth`：单链路带宽 Gbps（兼容旧命名 `bandwidth_per_link_gbps`）

未配置时自动降级，不影响既有设计流程。

### 4.2 Scale-Up 效果

- **GPU 节点**：生成 `scaleup_gpu` 节点，带 domain_id / protocol 属性，纳入机柜分配
- **全对等互联**：域内 GPU 全对等边自动生成（N*(N-1)/2 条）
- **机柜分配**：每 GPU 独立柜（Scale-Up 柜，琥珀色），域内柜号相邻
- **前端展示**：拓扑图渲染 Scale-Up 边，机柜视图展示 Scale-Up 柜

### 4.3 三种模板开箱即用

| 模板 | Scale-Up 配置 |
|------|--------------|
| NVL72-单架 | NVLink 72 GPU 单域 |
| ualink_1_0_1024 | UALink 1024 GPU 单域 |
| cloudmatrix_384 | UB 384 GPU 单域 |

## 5. 拓扑设计

### 5.1 设计入口

1. 左侧活动栏点击「拓扑设计」
2. 或菜单「项目 → 渲染输出」
3. 选择当前项目后显示设计面板

### 5.2 拓扑参数

**全模式（自动计算）**：系统根据服务器数量自动计算交换机数量与下行端口。

**自定义模式**：手动指定下行端口数：

- `param_downlink_limit` / `storage_downlink_limit` / `biz_downlink_limit` / `oob_downlink_limit`

**下行端口命名前缀**：参数网/存储网/带外网/业务网端口前缀自动按设备接口模型解析（如设备档案配置 "NIC" 则显示 NIC1、NIC2…）。

### 5.3 生成与校验

1. 点击「生成拓扑」，后端 Python 引擎计算
2. 自动执行 **19 条校验规则**（V001-V019）：
   - 拓扑连通性、端口溢出、设备一致性、PUE 合规
   - **V016** 服务器网卡总数 vs Leaf 下行容量
   - **V017** 光模块封装/距离/速率匹配
   - **V018** Pod / Scale-Up 域规模合理性
   - **V019** 整机房功耗 vs 供电容量
3. 通过则工作台状态显示「通过」，错误在日志面板详细展示

## 6. 机柜规划

### 6.1 机柜配置

- **机柜类型**：42U 或 49U
- **功率上限**：默认 6000W（按散热方式联动校验：风冷/冷板液冷/浸没式液冷）
- **命名前缀**：如「机柜」「Cabinet」

### 6.2 自动上架（多约束装箱）

生成拓扑后自动分配设备到机柜：

- 综合考虑功率、U 位、散热方式
- Scale-Up GPU 节点 **1 台/柜独占**（Scale-Up 柜）
- 功率 3 级色码监控：
  - 🟢 绿色：功率 < 60%
  - 🟡 黄色：60% - 80%
  - 🔴 红色：≥ 80%（超限告警）
- 自动计算所需机柜数量

### 6.3 手动调整

- 待分配设备池 → 点击 U 位放置，冲突自动检测
- 支持多机柜切换、设备跨柜移动
- 布局修改自动保存（500ms 防抖）

### 6.4 机房矩阵（V3.0.4）

机房视图支持以矩阵方式定义机房与落位：

- **创建矩阵**：进入「机房」Tab，设置行数（最多 26 行，对应 A~Z）与列数（最多 100 列），命名后点击「创建矩阵」。矩阵规模上限 4096 格（如 A15~O15=225 柜）。
- **占位标记**：工具栏选择「空调占位」/「柱子占位」后点击格子标记；再次点击同一格子可清除。占位位置不可放置机柜。
- **类型标记**：标记格子为 GPU/网络/存储/通算/组合柜；再次点击同一类型变回「未标记」。组合柜与未标记格允许任意类型机柜，其余格子仅允许对应类型。
- **拖拽上架**：左侧机柜面板按「已上架 / 未上架」分组列出所有机柜，拖拽到矩阵格子即可上架；已上架机柜拖到其他格子实现移动。
- **约束即时校验**：落位时校验占位阻止、机柜类型域、U 位溢出、功率超限（阻塞并提示）；功率密度超过 350W/U 提示散热风险（不阻塞）。
- **移除机柜**：选中已上架格子，工具栏出现「移除机柜」按钮。
- **保存**：点击「保存」经后端校验后写入项目 `room_layout.json`。

### 6.5 机房智能落位（V3.1.4）

创建矩阵并标记占位/类型后，可一键生成满足约束的落位方案：

- **智能落位入口**：机房矩阵工具栏点击「✨ 智能落位」，选择落位方式。
  - **按机柜落位**：将当前未上架的机柜自动填入空格（已上架机柜保持不动）；勾选「清空已上架重排」则全部机柜重新落位。机柜功率按设备自动累加。
  - **按数量落位**：填写 GPU/网络/存储/通算柜数量（如 115 / 45 / 45 / 15），按类型数量生成方案（格子以类型颜色标记，不上架具体机柜）。
- **约束自动满足**：空调/柱子占位自动跳过，机柜类型域（如网络柜区只放网络柜）与单柜功率上限自动约束，无需手动规避。
- **方案预览**：计算后展示已落位/未放置数量、耗时与四维目标评分——功率均衡 / 散热分区（高功率柜靠近空调）/ 网络就近（网络柜集中）/ 布线最短（同类型聚簇），以及综合评分；未放置原因（位置不足/超功率）逐条列出。
- **应用方案**：点击「应用方案」将落位结果写入矩阵，之后仍可拖拽手动调整、移除或重新标记；点击「保存」持久化到项目 `room_layout.json`。
- **对话驱动**：在 AIHUB 对话中直接描述需求（如"225 柜按 120 GPU + 60 网络 + 45 存储落位，柱子别挡"），AI 会自动创建/读取机房矩阵、按数量或机柜生成方案并汇报评分，确认后由前端应用。

## 7. 可视化

### 7.1 拓扑可视化

- **拓扑概览**：节点/连接统计、节点类型统计、Scale-Up 域信息
- **拓扑图**：交互式网络拓扑
  - 分层 × 分区 × 分组防重叠布局，参数网/存储网/业务网/OOB/Scale-Up 分区
  - **框选多节点拖动**、对齐工具栏（左/右/上/下）、Delete 删除节点（可撤销）
  - 链路悬浮高亮 + 详情（源端/目标端/速率/网络类型/缆型）
  - 节点悬浮显示类型/组/Pod/机柜/U位/功率/连接数
  - 边标签显示开关（缩放 <0.5 自动隐藏）
  - 小地图、缩放、拖拽
- **布局保存**：保存到 `topology.json`，重新生成保留已保存布局

### 7.2 机柜列表与 3D

- **机柜列表**：所有机柜概览（含 Scale-Up 柜）
- **Topology3D**：3D 可视化视图（空数据时显示引导）

### 7.3 暗色模式

自动跟随系统主题切换配色（MutationObserver 追踪，ECharts 同步更新）。

## 8. 输出导出

### 8.1 输出类型

| 输出类型 | 格式 | 说明 |
|---------|------|------|
| 连接关系表 | Excel | 全量连接关系（A 端/Z 端/速率/缆型） |
| 布线指导表 | Excel | 含光模块型号、长度估算、成本 |

## 13. 常见问题

### Q1: 生成拓扑失败怎么办？

A: ① 确认已选择项目；② GPU 服务器数量 > 0；③ 检查网络开关；④ 查看日志面板错误；⑤ 确认设备选型完整。校验规则 V016-V019 会给出容量/功率类具体错误。

### Q2: UEC 项目在配置校验时报非法？

A: V2.9.3 起 `validate_config` 已支持 UEC 协议（IB/RoCE/UEC）。请升级到 V2.9.3 及以上版本。

### Q3: Scale-Up 配置了但没效果？

A: 确认 `scale_up.num_gpus > 0` 且 protocol 为 NVLink/UALink/UB 之一；JSON 段与 INI section 二选一即可；旧配置无此段不影响使用。

### Q4: PDF 报告项目名称不对 / 机柜被截断？

A: V2.9.3 已修复：项目名称取 `meta.name`，机柜表全量渲染无 60 柜截断。请升级到 V2.9.3。

### Q5: 项目配置 INI 和 JSON 共存以哪个为准？

A: 以 `project_config.json` 为准（JSON 优先读取，支持更多功能）。INI 保留作备份。

### Q6: 如何将旧项目（V2.0 INI 格式）升级？

A: 系统自动检测旧格式并提示迁移，迁移生成 `project_config.json`，原 INI 保留。

### Q7: 切换项目后拓扑/机柜数据串扰？

A: V2.6.2+ 已修复：拓扑/机柜按项目持久化，Tab 状态按项目隔离，切换自动加载对应数据。

### Q8: 更新功能提示"已是最新"但实际有新版？

A: V2.7.7 修复了版本比较误报（严格版本比较 + 双通道）。请使用 V2.7.7 及以上版本。

### Q9: 工作区 Tab 异常或指向已删除项目？

A: 设置 → 数据管理 → 「重置工作区」一键恢复默认布局。

### Q10: 如何查看软件版本与软件栈？

A: 菜单「帮助 → 关于 AIDC AutoLink」，显示完整软件栈（Electron/Chromium/Node/React/Python）与版本号。

## 15. 容量规划

### 15.1 模型档案

内置 **17 个模型档案**（Llama/DeepSeek/Qwen/GPT 等 + 5 个国产场景：昇腾 910B/910C、寒武纪思元 590、海光 DCU、昆仑芯 P800，下拉标注「国产」来源），并支持用户自定义档案追加。

### 15.2 推荐向导

1. 在「拓扑设计」Tab 顶部点击「容量规划」入口
2. 选择训练模型 / 目标 GPU 数量 / 预算档位（经济/标准/旗舰）
3. 查看推荐结果：Scale-Up 协议与域规模、Scale-Out 速率与收敛比、层数建议
4. 点击「一键应用」将速率/协议/规模映射到当前项目

### 15.3 v2 精确计算（V3.2.0）

- **FP8 分块精确通信**：按激活/梯度/优化器状态精确估算通信量，展示与解析法误差对照
- **Pipeline 建模**：pp 分段显存估算（每 stage 参数与激活峰值）
- **TCO 成本**：硬件（交换机/网卡/光模块）+ 电力 + 机柜空间分项汇总
- **自定义档案**：在工作区 `capacity_presets.json` 追加档案，推荐可引用

## 16. ATOP 拓扑推荐

1. 在「拓扑」Tab 点击「ATOP 自动拓扑优化」
2. 选择模型（如 deepseek-v3）或填写通信特征，输入目标 GPU 规模
3. 查看推荐结果：
   - **通信特征**：通信模式（AllReduce / All-to-All / P2P）与通信占比
   - **cube 拓扑**：2D/3D 维度、Leaf 分组统计（A/B 组均衡着色）、链路规模
   - **校验结果**：V020 结构规则通过（无 error）
   - **推荐理由**：数据驱动的组网依据说明
4. 点击「应用到画布」一键生成 ZCube 拓扑并渲染

## 17. 批量优化与智能修复

### 17.1 批量优化

对话面板顶部工具栏点击「批量优化」：

1. 点击「生成建议」：按确定性规则批量产出收敛比 / 成本 / 散热三类建议（每条含修改字段与影响说明）
2. 支持全选 / 逐条勾选

### 17.2 智能修复

对话面板顶部工具栏点击「智能修复」：

1. 点击「生成修复方案」：运行完整校验，列出可自动修复的 error 级问题（rule_id 徽标 + 修复内容预览），需人工处理的单独分组
2. 支持全选 / 逐条勾选
3. 点击「一键修复」：应用修复 patch 后**自动复核**，展示剩余错误数变化（错误 → 修复 → 复核闭环）

可自动修复规则：V002 机柜功率 / V007 Rail / V010 收敛比 / V016 网卡容量 / V018 Scale-Up 域 / V019 供电 / V020 ZCube。
