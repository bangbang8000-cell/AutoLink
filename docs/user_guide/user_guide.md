## 1. 快速开始

### 1.1 首次启动

首次启动 AIDC AutoLink 时，系统会：

- 展示 **3 步引导**（创建项目 → 配置设计 → 可视化与交付），看过一次不再弹出
- 自动创建 3 个示例项目，方便快速体验：
  - **示例-H100-100台**：100 台 H100 GPU（入门示例）
  - **示例-H100-128台**：128 台 H100 GPU，4 组 Rail（Rail-Optimized 示例）
  - **示例-L20-推理-64**：64 台 L20 推理集群（推理场景示例）
- 内置 **16 套场景模板** 与 **118 款设备库**

### 1.2 界面布局

AIDC AutoLink 采用经典 IDE 风格布局：

| 区域 | 说明 |
|------|------|
| **顶部菜单栏** | 文件 / 编辑 / 视图 / 项目 / 帮助 |
| **左侧活动栏** | 项目浏览器 / 拓扑设计 / 机柜规划 / 可视化 / 设备库 / 设置 |
| **左侧文件浏览器** | 项目列表、输出文件、模板中心 |
| **中间工作区** | 标签页形式展示各功能面板（Tab 按项目隔离） |
| **右侧面板** | 日志输出 / 属性面板 |
| **底部状态栏** | 当前项目、状态信息 |

### 1.3 创建第一个项目

1. 点击左侧活动栏的「项目浏览器」图标
2. 点击顶部「+」按钮，或选择「从模板创建」
3. 在项目向导中填写（**分步校验**，无法继续时按钮下方会明确提示原因）：
   - **项目名称**：如 `我的第一个项目`（必填，≤50 字符，不能重名）
   - **GPU 服务器型号**：选择 H100 / B200 / 昇腾 / MLU590 等
   - **GPU 服务器数量**：如 100 台（上限 2048）
   - **参数网络协议**：IB / RoCE / **UEC**
   - **Scale-Up 配置**（可选）：protocol / num_gpus / domain_size / bandwidth
   - **存储/业务/带外网络**：按需开关
4. 点击「下一步」完成设备选型
5. 点击「完成」创建项目

## 2. 项目管理

### 2.1 项目列表

在左侧文件浏览器的「全部项目」区域可以看到所有项目。右键菜单支持：

- **设为当前项目** / **在文件管理器中打开** / **复制项目** / **重命名**
- **导出为 ZIP**：打包项目（含拓扑与机柜数据）为压缩文件
- **转为模板**：将项目保存为可复用模板
- **收藏置顶** / **删除项目**（不可恢复）

### 2.2 项目结构

```
项目名称/
├── project_config.json    # 项目配置（V2.1+ 格式，优先读取）
├── network_config.ini     # 网络配置（V2.0 格式，向后兼容）
├── project.json           # 项目元数据
├── topology.json          # 拓扑数据（含布局，自动保存）
├── rack_layout.json       # 机柜布局数据（500ms 防抖自动保存）
└── output/                # 输出文件目录
    ├── connection_table.xlsx
    ├── rack_table.xlsx
    └── topology.png
```

**数据持久化**：拓扑与机柜数据按项目保存，切换项目自动加载对应数据，重启后恢复；项目导出/导入 ZIP 完整保留。

**配置优先级**：`project_config.json` 与 `network_config.ini` 同时存在时，以 JSON 为准。

### 2.3 项目文件浏览

- **智能分组**（默认）：输入配置 / 输出文件 / 拓扑数据 / 其他文件，输出批次按时间倒序
- **真实分组**：按文件系统目录结构展示
- Excel / JSON / 图片 / 配置文件均可点击预览（Excel 一次性加载全部 Sheet，切换零重载）

### 2.4 模板中心

- 内置 16 套场景模板（H100 / L20 / NVL72 / SuperPOD / 昇腾 / 液冷 / UALink / CloudMatrix / UEC 等）
- 用户模板：通过「项目转模板」创建
- 支持模板编辑、导入、导出、删除、预览、健康检查
- 模板列表支持按场景/标签/名称搜索，并可筛选内置/用户模板
- 右键「预览方案」即时查看规模摘要与校验结果（临时生成，不落盘）

### 2.5 模板分享（导入/导出）

**导出模板为 ZIP**：右键模板 → 「导出为 ZIP...」，生成包含以下文件的压缩包：

| 文件 | 必选 | 说明 |
|------|------|------|
| `template.json` | 是 | 模板元数据（名称/描述/场景/标签/创建时间） |
| `project_config.json` | 推荐 | V2.1 项目配置（规模/网络/选型/机柜，JSON 与 INI 二选一或并存） |
| `network_config.ini` | 推荐 | V2.0 配置（旧格式，兼容历史工具） |

**导入模板**：工具栏「导入模板 ZIP」→ 选择压缩包，导入后自动写入用户模板目录。

**导入强校验**（V2.9.8）：
- ZIP 含 `project_config.json` → 自动执行配置校验（`validate_config`），**校验失败则拒绝导入并回滚**
- 仅含 `network_config.ini` → 自动调用 Python 迁移生成 `project_config.json` 后导入
- 两者皆无 → 明确拒绝（不是有效模板包）

导入成功后，模板列表自动刷新；可在「模板健康检查」中确认模板可用性。

### 2.6 模板健康检查

工具栏 ❤ 图标（模板健康检查）扫描全部内置 + 用户模板，定位损坏模板：

- 缺少 `project_config.json`（仅含 INI）
- `project_config.json` 解析失败
- 配置语义校验失败
- 选型引用失效（`device_refs` 引用的设备不在设备库中）

结果弹窗展示健康/异常汇总与逐项错误详情，便于定位并修复损坏模板。

## 4. Scale-Up 双栈规划

> v2.9 起 Scale-Up（GPU 卡间互联）与 Scale-Out（服务器间网络）双栈一体化规划正式转正。

### 4.1 启用 Scale-Up

在项目配置的 `scale_up` 段（JSON）或 `[scale_up]` section（INI）中配置：

```json
{
  "scale_up": {
    "protocol": "UALink",
    "num_gpus": 1024,
    "gpus_per_node": 8,
    "domain_size": 1024,
    "bandwidth": 200
  }
}
```

- `protocol`：NVLink / UALink / UB
- `num_gpus`：Scale-Up GPU 总数
- `domain_size`：单域规模（0 = 按协议默认）
- `bandwidth`：单链路带宽 Gbps（兼容旧命名 `bandwidth_per_link_gbps`）

未配置时自动降级，不影响既有设计流程。

### 4.2 Scale-Up 效果

- **GPU 节点**：生成 `scaleup_gpu` 节点，带 domain_id / protocol 属性，纳入机柜分配
- **全对等互联**：域内 GPU 全对等边自动生成（N*(N-1)/2 条）
- **机柜分配**：每 GPU 独立柜（Scale-Up 柜，琥珀色），域内柜号相邻
- **前端展示**：拓扑图渲染 Scale-Up 边，机柜视图展示 Scale-Up 柜

### 4.3 三种模板开箱即用

| 模板 | Scale-Up 配置 |
|------|--------------|
| NVL72-单架 | NVLink 72 GPU 单域 |
| ualink_1_0_1024 | UALink 1024 GPU 单域 |
| cloudmatrix_384 | UB 384 GPU 单域 |

## 5. 拓扑设计

### 5.1 设计入口

1. 左侧活动栏点击「拓扑设计」
2. 或菜单「项目 → 渲染输出」
3. 选择当前项目后显示设计面板

### 5.2 拓扑参数

**全模式（自动计算）**：系统根据服务器数量自动计算交换机数量与下行端口。

**自定义模式**：手动指定下行端口数：

- `param_downlink_limit` / `storage_downlink_limit` / `biz_downlink_limit` / `oob_downlink_limit`

**下行端口命名前缀**：参数网/存储网/带外网/业务网端口前缀自动按设备接口模型解析（如设备档案配置 "NIC" 则显示 NIC1、NIC2…）。

### 5.3 生成与校验

1. 点击「生成拓扑」，后端 Python 引擎计算
2. 自动执行 **19 条校验规则**（V001-V019）：
   - 拓扑连通性、端口溢出、设备一致性、PUE 合规
   - **V016** 服务器网卡总数 vs Leaf 下行容量
   - **V017** 光模块封装/距离/速率匹配
   - **V018** Pod / Scale-Up 域规模合理性
   - **V019** 整机房功耗 vs 供电容量
3. 通过则工作台状态显示「通过」，错误在日志面板详细展示

## 6. 机柜规划

### 6.1 机柜配置

- **机柜类型**：42U 或 49U
- **功率上限**：默认 6000W（按散热方式联动校验：风冷/冷板液冷/浸没式液冷）
- **命名前缀**：如「机柜」「Cabinet」

### 6.2 自动上架（多约束装箱）

生成拓扑后自动分配设备到机柜：

- 综合考虑功率、U 位、散热方式
- Scale-Up GPU 节点 **1 台/柜独占**（Scale-Up 柜）
- 功率 3 级色码监控：
  - 🟢 绿色：功率 < 60%
  - 🟡 黄色：60% - 80%
  - 🔴 红色：≥ 80%（超限告警）
- 自动计算所需机柜数量

### 6.3 手动调整

- 待分配设备池 → 点击 U 位放置，冲突自动检测
- 支持多机柜切换、设备跨柜移动
- 布局修改自动保存（500ms 防抖）

## 13. 常见问题

### Q1: 生成拓扑失败怎么办？

A: ① 确认已选择项目；② GPU 服务器数量 > 0；③ 检查网络开关；④ 查看日志面板错误；⑤ 确认设备选型完整。校验规则 V016-V019 会给出容量/功率类具体错误。

### Q2: UEC 项目在配置校验时报非法？

A: V2.9.3 起 `validate_config` 已支持 UEC 协议（IB/RoCE/UEC）。请升级到 V2.9.3 及以上版本。

### Q3: Scale-Up 配置了但没效果？

A: 确认 `scale_up.num_gpus > 0` 且 protocol 为 NVLink/UALink/UB 之一；JSON 段与 INI section 二选一即可；旧配置无此段不影响使用。

### Q4: PDF 报告项目名称不对 / 机柜被截断？

A: V2.9.3 已修复：项目名称取 `meta.name`，机柜表全量渲染无 60 柜截断。请升级到 V2.9.3。

### Q5: 项目配置 INI 和 JSON 共存以哪个为准？

A: 以 `project_config.json` 为准（JSON 优先读取，支持更多功能）。INI 保留作备份。

### Q6: 如何将旧项目（V2.0 INI 格式）升级？

A: 系统自动检测旧格式并提示迁移，迁移生成 `project_config.json`，原 INI 保留。

### Q7: 切换项目后拓扑/机柜数据串扰？

A: V2.6.2+ 已修复：拓扑/机柜按项目持久化，Tab 状态按项目隔离，切换自动加载对应数据。

### Q8: 更新功能提示"已是最新"但实际有新版？

A: V2.7.7 修复了版本比较误报（严格版本比较 + 双通道）。请使用 V2.7.7 及以上版本。

### Q9: 工作区 Tab 异常或指向已删除项目？

A: 设置 → 数据管理 → 「重置工作区」一键恢复默认布局。

### Q10: 如何查看软件版本与软件栈？

A: 菜单「帮助 → 关于 AIDC AutoLink」，显示完整软件栈（Electron/Chromium/Node/React/Python）与版本号。
