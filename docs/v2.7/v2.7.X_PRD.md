## 一、背景与定位

### 1.1 产品定位

AutoLink 是 **AI 智算中心网络规划与可视化工具**,卡位"建前规划"环节:

```
NVIDIA Fabric Manager / DCGM  ← 运行时管理(建后)
DCIM 平台                      ← 运维监测(建后)
═══════════════════════════════════════════
AutoLink                       ← 规划设计(建前)  ← 本产品定位
═══════════════════════════════════════════
通用 CAD/Visio                 ← 通用绘图(无领域智能)
```

纯"网络规划设计"赛道专业竞品稀缺,Fabric Manager 是建后管理、DCIM 是建后运维,AutoLink 守住"建前规划"的独特定位。

### 1.2 v2.7.0 基线

v2.7.0 完成了产品原型,核心能力包括:

- Rail-Optimized / Fat-Tree 拓扑设计(参数网/存储网/业务网/OOB)
- 拓扑可视化(react-flow)、机柜 U 位规划、PUE 估算、光模块选型
- 109+ 设备库、11 套场景模板
- Excel/PDF 专业导出、5 语言 i18n
- 自动更新(双通道检查 + 正向下载)
- 拖拽线颜色修复、项目浏览器目录显示修复

### 1.3 v2.7.X 演进目标

**六维度演进方向**:

| 维度 | 目标 | 关键举措 |
|------|------|----------|
| **更好用** | 交互零摩擦 | 快捷键全局注册、ContextMenu 边界检测、ResizableAppLayout 持久化 |

| **更高效** | 性能无阻塞 | 拓扑布局 Web Worker、Python 持久进程、Excel 算法优化 |

### 2.1 阻断性 Bug(P0,影响核心功能)

| 编号 | 问题 | 影响 | 位置 |
|------|------|------|------|
| B1 | **validation.py 的 10 条规则完全未接入 engine.py** | 用户看不到收敛比/Rail 一致性/U 位冲突等结构化校验,仅显示端口溢出 | `backend/engine.py` 仅调 `designer.validate_topology()` |
| B2 | **Rail-Optimized 连接 a_module/z_module 为空字符串** | 导出 Excel 时光模块选型失效 | `backend/rail_topology.py` L158,173,186 |

| B4 | **Rail-Optimized 服务器分配为连续分块** | NVIDIA SuperPOD 标准是交错分配(NIC_i ↔ Rail_i),连续分块导致单 Rail 故障集中 | `backend/rail_topology.py` L144-151 |
| B5 | **`design:generate` 删除 project_config.json** | rail_mode/param_protocol 等扩展字段永久丢失,Rail-Optimized 不可用 | `electron/ipc/handlers.ts` L549-551 |

| B7 | **VERSION 文件与 package.json 不同步** | VERSION=2.6.9 vs package.json=2.7.0,发布元数据不一致 | `VERSION` 文件 |
