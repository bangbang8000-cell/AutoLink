# AutoLink v2.9.4 ~ v2.9.9 产品 PRD：项目模板生命周期打通

> 版本: 1.0 ｜ 日期: 2026-08-02 ｜ 状态: 待评审
> 系列主题: **项目模板生命周期打通 —— 让"模板创建 → 沉淀 → 复用 → 编辑 → 分享"全流程闭环可用**

---

## 一、背景与定位

### 1.1 问题背景

用户反馈**无法从项目模板创建项目**。经对前端、Electron IPC、后端 Python 全链路代码审查，确认模板功能存在**三重断链**，导致"从模板创建项目"这一核心业务实际不可用：

1. **前端无入口**：带模板选择的新建弹窗 `CreateProjectModal.tsx` 是**死代码**（零引用）；"新建项目"按钮只打开从零开始的向导 `CreateProjectWizardModal`（且不传 `templateName`）；模板右键菜单没有"基于此模板创建项目"。
2. **后端复制缺陷**：`project:create` 从模板创建时**只查内置模板路径**（用户模板被静默跳过，产出空项目）、**只复制 `network_config.ini`**（不复制 `project_config.json`，设备选型/机柜配置全部丢失）。
3. **模板数据不完整**：16 个内置模板目录仅有 `template.json` + `network_config.ini`（V2.0 格式），**缺少 `project_config.json`**（规模设置/选型设置/机柜设置的载体）；向导里的 `templateName` 只显示提示文字、不加载任何模板数据。

### 1.2 产品定位

v2.9.4 ~ v2.9.9 定位为**项目模板生命周期打通版本**：让模板成为"可复用的完整方案配置"，让用户能够**基于模板一键创建项目**、**可视化编辑模板**、**预览模板规模/选型**，并保证模板与项目、内置模板与用户模板、开发与打包环境之间数据形态一致。

### 1.3 演进目标

| 维度 | 目标 | 关键举措 |
|------|------|----------|
| **更完整** | 模板包含完整方案配置 | 模板补齐 `project_config.json`（规模/选型/机柜），内置 16 模板全部治理 |
| **更顺畅** | 一键从模板创建项目 | 模板右键"基于此模板创建项目" + 向导模板预加载 + 后端全量复制修复 |
| **更可编辑** | 模板可视化编辑 | 编辑弹窗从"纯 INI 文本"升级为"规模/选型/机柜表单" |
| **更可感** | 模板所见即所得 | 模板卡片展示规模摘要，预览即时生成拓扑/机柜估算 |
| **更可信** | 模板库质量受控 | 模板验证全覆盖、健康检查、导入导出强校验 |

## 二、现状评估（基于 2026-08-02 代码审查）

### 2.1 断链根因（P0，为什么"无法从模板创建项目"）

| 编号 | 问题 | 影响 | 位置 |
|------|------|------|------|
| T1 | **`CreateProjectModal.tsx`（模板选择新建弹窗）是死代码**：全仓库零引用，仅定义处 1 处命中 | 无任何 UI 允许用户选模板建项目 | `src/components/sidebar/CreateProjectModal.tsx` |
| T2 | **"新建项目"只打开向导且不传模板**：`App.tsx:236` 调用 `CreateProjectWizardModal` 未传 `templateName`；`wizard.store.templateName` 仅在 `WizardStepBasic` 显示"基于模板: xxx"文字，**不加载模板任何数据**（规模/选型/机柜全空） | 向导 = 永远从零开始 | `src/App.tsx`、`src/stores/wizard.store.ts`、`src/components/wizard/WizardStepBasic.tsx:33-40` |
| T3 | **模板右键菜单无"基于此模板创建项目"**：V2.4.1 PRD 规划的"已有"功能实际未实现；菜单仅含 查看文件/资源管理器打开/导出ZIP/编辑/删除 | 无法从模板中心直接建项目 | `src/components/layout/TemplateSection.tsx:201-212` |
| T4 | **`project:create` 只查内置路径**：`options.template` 时 `path.join(getTemplatePath(), template)`，**用户模板（`user-templates`）不在该目录 → 找不到 → 静默落空**（既不复制模板配置也不复制默认配置，产出仅含 `project.json` 的空项目） | 用户模板创建项目 = 空项目，静默数据错误 | `electron/ipc/handlers.ts:287-298` |
| T5 | **`project:create` 只复制 `network_config.ini`**：即使内置模板命中，也只复制 INI，不复制 `project_config.json`（若有）| 项目缺失设备选型/机柜配置，与向导产出形态不一致 | 同上 |
| T6 | **迁移函数不适配模板 INI**：`migration.ini_to_project_config` 读取 `[topology]` 段，而模板 INI 全部使用 `[DEFAULT]` 段（V2.0 格式） | 自动迁移无法直接用于模板，补齐 JSON 需扩展迁移逻辑 | `backend/migration.py:75-131`、`template/*/network_config.ini` |

### 2.2 模板数据完整性（P0，模板"没有文件"）

当前每个内置模板目录仅 2 个文件：

```
template/H100-100台/
├── template.json          # 元信息：id/name/description/scenario/tags/updatedAt
└── network_config.ini     # V2.0 [DEFAULT] 段配置
```

**缺失文件与用户诉求映射**：

| 用户认知 | 数据载体 | 现状 | 预生成方案 |
|----------|----------|------|------------|
| 规模设置 | `project_config.json.topology`（GPU/存储/通算数量、端口/速率、downlink_limit、param_protocol、rail_mode） | ❌ 仅 INI 中的一部分 | **必须预生成**（模板核心配置） |
| 选型设置 | `project_config.json.device_refs`（gpu_server / 各层交换机 / 存储服务器 / 光模块的 `{ref_id, device_id}` 引用） | ❌ 完全缺失 | **必须预生成**（按网络开关 + param_protocol 自动选型后人工校准） |
| 机柜设置 | `project_config.json.rack_config`（rack_type / power_limit / naming_prefix / cooling_method / gpu_dedicated） | ❌ 完全缺失 | **必须预生成** |
| 网络开关 | `project_config.json.networks`（param/storage/biz/oob） | ⚠️ 可从 INI 推导 | **必须预生成** |
| 派生预览（拓扑/机柜布局） | `topology.json` / `rack_layout.json` | ❌ 缺失 | **不落盘**：由 `project_config.json` 即时生成用于预览，避免模板臃肿与配置漂移 |
| 模板健康 | 验证结果 | 部分（validate_templates.py 覆盖 16 模板但只查 INI） | 升级：校验 JSON 完整性 + 选型可解析 + 机柜不超限 |

> 结论：**模板应预生成 `project_config.json`（规模/选型/机柜/网络的唯一权威载体）；`topology.json` / `rack_layout.json` 属于派生数据，预览时即时生成、不落盘。**

### 2.3 模板 ↔ 项目业务流现状

```
【沉淀方向】项目 → 另存为模板
  ✅ template:create 复制 project_config.json + network_config.ini + project.json
  ⚠️ 但内置模板库本身没有 project_config.json → 用户另存为模板与内置模板数据形态不一致

【复用方向】模板 → 项目
  ❌ 前端无入口（T1/T2/T3）
  ❌ 后端只复制 INI、只查内置路径（T4/T5）

【编辑方向】模板修改
  ⚠️ EditTemplateModal 只能编辑元信息 + INI 文本，不能可视化编辑 device_refs / rack_config

【分享方向】模板导入/导出
  ✅ ZIP 导入导出已实现（白名单含 project_config.json）
  ⚠️ 导入校验只要求 network_config.ini 或 project_config.json 二选一，未强校验 JSON 完整性
```

## 三、核心设计

### 3.1 模板数据模型升级（v2.9.4）

**新模板目录标准结构**：

```
template/<模板名>/
├── template.json          # 元信息（保留，新增 templateVersion: 2）
├── network_config.ini     # V2.0 兼容配置（保留，向后兼容旧流程）
└── project_config.json    # V2.1 完整配置（新增，必选）—— 规模/选型/机柜/网络的唯一权威载体
```

`project_config.json` 结构对齐 `backend/project_config.py` 的 `DEFAULT_PROJECT_CONFIG`：

```json
{
  "meta": { "name": "...", "description": "...", "version": 1 },
  "networks": { "param_network": true, "storage_network": true, "biz_network": true, "oob_network": true },
  "topology": { "downlink_mode": "custom", "param_protocol": "RoCE", "num_gpu_servers": 100, "...": "..." },
  "device_refs": { "gpu_server": {"ref_id": "gpu_server", "device_id": "nvidia_dgx_h100"}, "...": "..." },
  "rack_config": { "rack_type": 42, "power_limit_per_rack": 6000, "naming_prefix": "机柜", "cooling_method": "air", "gpu_dedicated": false },
  "scale_up": {}
}
```

**一致性约束**：
- `project_config.json` 为权威，`network_config.ini` 由脚本生成并保持同步（或反向：INI 为源、JSON 由生成脚本产出，二者必须等价）——**推荐 JSON 为权威，INI 为兼容视图**；
- 模板加载优先级与项目一致：`project:getConfigFile` 已实现 INI→JSON 自动迁移，模板补齐 JSON 后无需迁移。

### 3.2 模板预生成脚本（v2.9.4）

新建 `scripts/prepare_templates.py`，一键处理 `template/` 下全部模板目录：

1. **INI → JSON**：扩展 `migration.ini_to_project_config` 支持 `[DEFAULT]` 段读取（复用 designer 的 `_load_common_ini_config` 字段映射），产出 topology/networks/rack_config；
2. **自动选型**：按 `networks` 开关 + `param_protocol` 生成默认 `device_refs`（复用 `WizardStepDevices.tsx` 的 IB/RoCE 默认映射表与 `designer.py:_auto_select_param_switch` 的选型逻辑，两端规则收敛到后端一份实现）；
3. **验证**：对生成的 `project_config.json` 运行 `validate_config` + `NetworkDesignerV2` 设计 + 机柜不超限检查；
4. **INI 同步**：若 JSON 为权威，则从 JSON 反向生成 `network_config.ini` 保证等价；
5. **幂等**：脚本可重复运行，不破坏人工校准过的 device_refs（检测到已有 JSON 时只报告差异不覆盖，或提供 `--force`）。

### 3.3 从模板创建项目链路（v2.9.5）

**后端**（`electron/ipc/handlers.ts`）：
- `project:create` 修复：
  - 模板查找顺序：**用户模板 → 内置模板**（`getUserTemplatePath()` 优先，与 `template:getStructure` 一致）；
  - 复制范围：`project_config.json` + `network_config.ini`（模板根目录全部配置文件）；
  - 模板不存在时**抛错**（不再静默产出空项目）；
  - 新增 `project:createFromTemplate`（或复用 createWithConfig）：读取模板 `project_config.json` → 改写 `meta.name/created_at` → 写入新项目目录 → 同时生成兼容 INI。推荐**复用 `project:createWithConfig`**：前端读取模板 JSON 后直接调用，后端无需新接口。

**前端**：
- 模板右键菜单新增 **"基于此模板创建项目"**（`TemplateSection.tsx`）→ 打开 `CreateProjectWizardModal({ templateName })`；
- 向导模板预加载（`CreateProjectWizardModal` / `wizard.store.openWizard`）：
  - 读取模板 `project_config.json`（新增 IPC `template:getConfig` 或复用 `template:getFile`）→ 预填 `config`（networks/topology/device_refs/rack_config）；
  - `meta.name` 预填为 `${模板名}`（可改），描述预填模板描述；
  - `WizardStepBasic` 显示"基于模板: xxx"横幅，并允许查看模板详情；
  - 创建时 `createProjectWithConfig` 写入项目，模板与项目数据完全一致；
- 删除死代码 `CreateProjectModal.tsx`（或改造为模板详情弹窗，见 v2.9.7）。

### 3.4 模板可视化编辑（v2.9.6）

`EditTemplateModal` v2 从"元信息 + INI 文本"升级为**结构化表单 + 原文兜底**：

| 区块 | 内容 | 控件 |
|------|------|------|
| 元信息 | 名称/描述/场景/标签 | 文本/多行/单选/标签输入（保留） |
| 规模设置 | GPU/全闪/混闪/通算数量、端口数、速率、下行限制、协议、rail_mode | 数值/下拉（复用 WizardStep 控件） |
| 网络开关 | param/storage/biz/oob 四开关 | Toggle（复用） |
| 选型设置 | 各网络对应设备引用（GPU 服务器/参数 Leaf/Spine/Core/存储/业务/OOB/光模块） | `DeviceLibraryPicker` 复用（只读预览 device_refs 并允许替换） |
| 机柜设置 | rack_type / 功率 / 命名前缀 / 散热 / gpu_dedicated | 表单（复用 WizardStepRack 控件） |
| 原文兜底 | `project_config.json` / `network_config.ini` 文本编辑 | 折叠面板 + 保存前 JSON 校验 |

保存路径：`template:update` 扩展支持 `projectConfig?: string`（JSON 文本），后端校验 JSON 合法性后写回；同时**从 JSON 反向同步 INI**（保证兼容）。

### 3.5 模板预览与派生文件（v2.9.7）

- **模板卡片摘要**：模板列表项展示规模摘要（GPU 台数 / 交换机估算 / 机柜估算 / 协议 / 功率），数据来自模板 `project_config.json`（无需后端计算）；
- **即时预览**：模板右键"预览方案"→ 后端按模板 `project_config.json` 执行设计（复用 `design:generate` 引擎，临时目录）→ 返回拓扑摘要（服务器/交换机/机柜/功率/收敛比）→ 前端弹窗展示；**不落盘**（`topology.json`/`rack_layout.json` 为派生数据）；
- 预览失败时给出具体校验错误（选型缺失/规模非法等），引导用户进入模板编辑。

### 3.6 模板生命周期管理增强（v2.9.8）

- **导入强校验**：`importTemplateZip` 要求模板 ZIP 含 `project_config.json`（合法 JSON + `validate_config` 通过）或 `network_config.ini`；导入后若缺 JSON 自动触发生成；
- **模板健康检查**：启动时或手动扫描模板库（内置 + 用户），输出不健康模板清单（缺 JSON / JSON 非法 / 选型引用失效 / 设计失败），`validate_templates.py` 升级为全套检查并纳入 CI 门禁；
- **编辑同步**：模板编辑/导入后，`fetchTemplates` 缓存自动失效刷新；
- **模板列表增强**：场景/标签筛选、内置/用户标识、规模摘要列（与 3.5 摘要共用）。

### 3.7 收口与回归（v2.9.9）

- 修复 `scripts/test_export.py` 既有 TypeError（unhashable: LibraryDevice）；
- 全量质量门禁：`tsc --noEmit` + `eslint` + `vitest` + `pytest` + `validate_templates.py` 全绿；
- 用户指南更新：模板创建/复用/编辑/分享操作说明；
- 发布：版本号同步（package.json / VERSION / package-lock.json）→ CHANGELOG → commit（[skip ci]）→ tag。

## 五、非功能需求

### 5.1 性能
- 模板预览（设计引擎临时跑）：2048 台级 < 3s；
- 模板列表加载（含 16 内置 + N 用户模板）：< 500ms，摘要本地解析不阻塞主线程。

### 5.2 质量
- `scripts/prepare_templates.py` 与 `validate_templates.py` 可作为 CI 门禁，0 error 方可发布；
- 每个版本发布前必须通过：`tsc --noEmit` + `eslint` + `vitest` + `pytest` + 模板验证，0 error 方可打 tag。

### 5.3 兼容性
- 旧模板（仅 INI）仍可被 `project:create` / 导入流程处理（自动生成 JSON 或明确提示），不静默失败；
- `project_config.json` schema 向后兼容（新增字段带默认值）；
- 用户模板与内置模板行为一致（创建/编辑/预览）。

### 5.4 国际化
- 所有新增文案支持 5 语言（zh-CN / en / ja / ko / zh-TW），i18n key 完整性测试覆盖。

## 六、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 自动选型与人工期望不符（device_refs 校准量大） | 中 | R1.4 脚本生成后人工校准；选型规则收敛到后端一份实现，前端一致 |
| INI↔JSON 双向同步产生字段漂移 | 中 | JSON 为权威，INI 为兼容视图；验证脚本断言等价 |
| 向导模板预加载破坏既有创建流程 | 中 | 预填可覆盖可清空；默认值对象不变；vitest 覆盖 store |
| 预览引擎在用户模板上执行耗时/失败 | 中 | 临时目录 + 超时保护；失败返回具体错误引导编辑 |
| 内置模板目录在打包环境只读 | 低 | 内置模板只读 + 编辑/创建引导"另存为模板"，与现有 isBuiltin 策略一致 |
