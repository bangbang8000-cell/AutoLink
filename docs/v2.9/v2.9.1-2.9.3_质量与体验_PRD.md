# AutoLink v2.9.1-2.9.3 质量与体验 PRD

> 版本: 1.0 ｜ 日期: 2026-08-02 ｜ 状态: 待评审
> 系列主题: **质量工程闭环 · 使用体验精细打磨 · 能力补强收口**（v2.9.0 机柜规划发布后，进入 3.0 前的收官阶段）

---

## 一、背景与定位

### 1.1 背景

v2.9.0 完成了机柜规划与上架逻辑重构，规划能力已贴近现实。但经三轮深度审计（后端能力 / 代码质量 / 前端体验），发现产品在进入 v3.0「AI 辅助容量规划」之前，存在三类必须收口的欠账：

1. **工程质量欠账**：7 个前端死代码文件、多处重复逻辑、多处"仅 console.error"的静默失败、`ub_topology.py` 零测试、2048 大规格性能热点；
2. **体验欠账**：空状态大面积缺失（含 3D Tab 白屏）、ui/ 组件库造好未用、切换项目 Tab 数据串扰、长耗时操作反馈失真、无首次引导；
3. **能力欠账**：Scale-Up（UB/NVLink/UALink）双栈是"半成品"（后端未接入主流程、无机柜分配、前端空转）、校验引擎缺容量类硬规则、PDF 报告存在 bug 与信息缺失、UEC 协议前后矛盾、3 个 Scale-Up 模板名实不符。

### 1.2 产品定位

v2.9.1-2.9.3 定位为 **3.0 前的收官阶段**：不新增大型方向，而是让已有能力"转正、补全、打磨"，使产品在功能、质量、体验三个维度达到可稳定交付的状态。

### 1.3 演进目标

| 维度 | 目标 | 关键举措 |
|------|------|----------|
| **更可靠** | 无死代码、无静默失败、错误用户可见 | 死代码清理、重复合并、错误反馈补齐 |
| **更好用** | 空态有引导、操作有反馈、组件风格统一 | 空状态统一、组件库落地、loading 真实化 |
| **更完整** | 双栈转正、校验补硬规则、报告无失真 | Scale-Up 接入、V016-V019、PDF 修复 |
| **更一致** | 协议/模板/数据前后一致 | UEC 修矛盾、模板治理、Tab 按项目隔离 |

## 四、非功能需求

### 4.1 性能指标
- 2048 台服务器设计耗时 < 2s（当前 3-8s）
- 超大 Excel（>10 万行）解析不冻结主线程（worker/分片）
- 1000+ 机柜报告 PDF 完整输出（分页，不截断）

### 4.2 质量指标
- `ub_topology.py` 分支覆盖率 ≥ 70%（新增测试）
- 每个版本发布前必须通过：`tsc --noEmit` + `eslint` + `vitest` + `pytest`，0 error 方可打 tag
- eslint `no-explicit-any` 恢复 error（v2.9.1 起）

### 4.3 兼容性
- 删除 sidebar/ 死代码不影响任何既有功能（先行确认零引用）
- Tab 隔离不破坏已保存的 workspace 持久化（版本迁移 +1）
- Scale-Up 配置为可选段，旧项目（无 scale_up 段）行为与 v2.9.0 一致

## 五、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| Scale-Up 接入涉及配置/生成/机柜/前端/报告全链路，工作量最大 | 高 | 拆 5 个子任务逐步落地，先行最小闭环（配置→生成→前端展示）再补机柜/报告 |
| Tab 项目隔离改变既有交互（关闭确认） | 中 | 仅对含 dirty 状态的 Tab 拦截；保留"未保存"标记 |
| Excel worker 化重构风险 | 中 | 先分片 + 进度（低风险）再 worker（可选）；vitest 覆盖 |
| 性能优化改变分配顺序（柜号变化） | 低 | 分桶索引保持同类型内输入顺序，测试锁定柜号连续性 |
| eslint 规则收紧引发存量告警 | 中 | v2.9.1 内完成 any 治理后恢复 error；CI 门禁同步 |
