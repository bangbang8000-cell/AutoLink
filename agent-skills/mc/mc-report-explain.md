# MC 结果解读与汇报

## 一、汇报模板

```
【渲染结果】项目「机房A-接入交换机」
  模板：templates/ASW.j2（华为 S5735）
  设备数：24 台
  产物：output/ 下 24 个 .cfg 文件
  校验：模板语法 ✅ / Excel 数据 ✅ / 交叉引用 ✅
  差异：与上次相比，12 台设备的 VLAN 段有变化
```

## 二、⚠️ 渲染失败的归因话术（**按这个顺序说**）

| 报错 | 归因 | 怎么跟用户说 |
|---|---|---|
| `UndefinedError: 'xxx' is undefined` | **模板变量 Excel 里没有**（或名字不一致） | 「模板里的 `xxx` 在 Excel 表头里找不到。要不要我把表头的实际名字列出来对一下？」 |
| 渲染出来缺行 / 为空 | **Excel 表头与模板变量名不一致** | 「表头写的是『主机名』，模板读的是 `hostname`——需要统一」 |
| 语法错误 | Jinja2 模板本身写错 | 「模板第 N 行语法有问题」+ `validate_template` 的原文 |
| 渲染成功但内容不对 | **口径类缺陷**（分光/速率/机柜） | 见 §5 |
| `validate_*` 全过但 `dry_run` 报错 | **100% 变量名不一致** | 直接说「这是变量名不匹配，不是语法问题」 |

> **不要只说「渲染失败了」** —— 用户需要知道**改哪里**。

## 三、产物说明

渲染/导出的产物对应关系：

| 工具 | 产物 | 落点 |
|---|---|---|
| `render_config` | 设备配置文件 | `output/` |
| `render_yaml` | YAML 文件 | `output/`（yaml） |
| `generate_labels` | Word 标签 | 项目内 |
| `generate_label_md` | Markdown 标签 | 项目内（程序内可直接看） |
| `export_project` | zip 包 | **`workspace/_exports/<项目名>.zip`** |
| `dry_run` | **预览文本（不落盘）** | — |
| `preview_template` | **预览文本（不落盘）** | — |

→ 用户问「产物在哪」→ 按上表答。**`dry_run` / `preview_template` 不产生文件**，别说成「生成好了」。

## 四、`analyze_project` 结果的解读

返回四块，汇报时按「先问题后建议」组织：

| 块 | 怎么讲 |
|---|---|
| 模板复杂度 | 「模板 N 层嵌套 / M 个变量」——只在复杂度异常高时提 |
| 变量使用 | **「定义了没用的」**「**用了没定义的**」← 后者是重点 |
| Excel 数据质量 | 空值 / 类型 / 重复行 —— 具体到行号 |
| **交叉引用** | **最有价值** —— 「模板引用 X，Excel 里没有」 |

> 汇报要**落到具体**：「某几个变量未被使用」不如「`snmp_community` 定义了但模板没引用」。

## 五、⚠️「确实是缺陷」清单（MC 侧）

| 缺陷 | 表现 | 影响 |
|---|---|---|
| **MC 设备库仅 13 台** | 无 H200 / B300 / Q3400 / Spectrum-X | 新场景模板无法落 |
| **`project_single.py:423`** | **无条件产全部角色 j2** | 不能按需只出部分角色 |
| **B300 档案** | 描述 2×400G vs 字段 8×800G | 以**字段 8×800G** 为准 |
| **Q3400 描述** | 写 NDR，应为 **XDR** | 文案缺陷 |
| **`switches/storage/`** | 5 台全以太，**无 IB 存储交换机** | 查不到是缺件 |
| **MC 权限表** | 10 个工具未登记（`task_*`×5 + `audit_query` + `agent_feedback` + `run_cli`/`list_dir`/`read_source`） | 兜底 confirm |
| **`create_project` 名实不符** | 描述说「从 example 复制」，别名却指向 `create_project_intelligent` | 易误用 |

→ **报告缺陷时同步给出「那它从哪来」**（方法论 M4）。

## 六、⚠️「看起来是 bug，其实是设计」清单

| 现象 | 真相 |
|---|---|
| `create_project` 行为和描述不符 | 别名表导致，**是设计**（但确实反直觉） |
| `disable_skill` 没删技能 | **正确**，只控制是否进上下文 |
| `undo_render` 只能撤一次 | **设计如此**，非多级回滚 |
| `export_project` 是 🟢 auto | 只打包不写项目文件 |
| `read_file` 编译态可用 | **MC 的设计**（AL 不可用） |
| 模板中心改动影响新建项目 | **正确**，模板中心是共享源 |

## 八、常见坑

| 坑 | 正解 |
|---|---|
| 只说「渲染失败了」 | 给归因 + 改哪里 |
| 把 `dry_run` 说成「生成好了」 | 它是预览，不落盘 |
| 汇报分析结果太笼统 | 落到具体变量名 / 行号 |
| 把 MC 的 `undo_render` 当多级回滚 | 只撤一次 |
| 用 AL 的数字答 MC 的问题 | 见 §7 事实表 |
| 只报缺陷不给来源 | 同步给「从哪来」 |
