# AL 设备库与选型

## 一、三个查询工具（🟢 全 auto）

```
device_query    {"category": "switches", "query": "400G", "limit": 50}
device_get      {"deviceId": "nvidia_mqm9700_64_400g_ib"}
device_defaults {"protocol": "IB", "gpu_library_id": "nvidia_dgx_h200"}
```

| 工具 | 何时用 |
|---|---|
| `device_query` | 用户问「有哪些 XX 设备」；`category` 支持**前缀**（`switches` 会命中 `switches/...` 全部子类） |
| `device_get` | 已有 `library_id`（如从 `plan.json` 的 `device_refs[*].library_id` 反查） |
| `device_defaults` | 用户问「默认/推荐用什么交换机」—— **这个是首选**，返回的是与产品向导一致的规则 |

**`device_defaults` 的规则**：按协议（IB / RoCE / UEC）× GPU 世代
- `gb300` / `nvl72` / `b200` / `b300` → **800G**
- 其余 → **400G**

返回四张网的默认交换机（`refKey → 设备库 id`）：参数网 / 存储网 / 业务网 / 带外网。

> ⚠️ 用户问「默认用什么」时**先调 `device_defaults`，不要自己从 `device_query` 结果里挑** —— 前者是产品口径，后者是全量清单。

## 二、设备库规模事实（回答数量类问题时用）

- **127 台** = 92 硬件 + 35 光模块
- 模板 23 套；校验规则 22 条（V001–V022）

> 不要引用文档里的旧数字，以上为实测值。查询后如需精确计数，以 `device_query` 返回为准。

## 三、⚠️ 光模块选型的三条硬约束

### 约束 1：速率解析必须单位感知（**T = ×1000**）

`'1.6T'` 必须解析为 **1600**，不是 `1`。同仓有**四份**速率解析实现：

- `optical_selector._parse_speed`
- `exporter`
- `engine`
- `validation`

→ **改任何一份，必须核对另外三份**。外部 Agent 读到速率字段时，若看到 `1` 或 `1.6` 而非 `1600`，**先怀疑单位解析缺陷**，不要当成真实值。

### 约束 2：降级只许「同速档内放宽光纤类型」，**绝不跨速率**

选不到匹配光模块时的降级路径：
- ✅ 400G 内换光纤类型（如 SMF → MMF）
- ❌ 400G 降到 200G，或 400G 升到 800G

### 约束 3：三态必须守恒

`select_optical_module` 返回三态：`matched` / `not_applicable` / `unmatched`

**`matched + not_applicable + unmatched` 必须等于唯一连接数。**

- 铜缆 / 双绞线族 → `not_applicable`（**`DAC` / `铜缆` 不豁免**）
- 三态之和 ≠ 连接数 → **是缺陷，不是正常结果**，要向用户报告

> ⚠️ 调 `select_optical_module(...)` 时 `library` 参数在第 **5** 位 → **一律用关键字传参**，别用位置参数。

## 四、⚠️ 分光（breakout）必须「按网络角色」生效

**同型号设备在不同网上分光策略可以不同：**

| 设备 | 参数网 | 存储网 |
|---|---|---|
| IB `QM9700` | **1:1（不分光）** | **400G → 2×200G（分光）** |
| RoCE `X400`（浪潮 SC8670EL-128QH） | 1:1 | 1:1 |

→ **设备的 `breakout` 字段不是全局开关**，不能读一次就套到所有网上。

**已知缺陷 P-5**：QM9700 档案硬带 `breakout 400G→2×200G`，经 `_link_speed_for()` 会把**参数网也降到 200G**。
→ 外部 Agent 看到「IB 参数网被算成 200G」时，**这是缺陷不是设计**，应报告。

## 五、⚠️ 「每服务器口数」必须按服务器类别给值

「每服务器口数」类参数**不能是单值**：

| 网络 | GPU 服务器 | 存储服务器 |
|---|---|---|
| 存储网 | **1 口** | **4 口** |

**已知缺陷 P-6**：`storage_ports_per_server` 现为单值（默认 1）⇒
**建链口数 / 层级判据 / 容量校验（V016 按 breakout 放大）三处不同源**，GPU 的 1 口与存储的 4 口无法同时表达。

→ 外部 Agent 若发现「层级判定结果与连接表口数对不上」，根因大概率在此。

正确做法应照抄 `AccessAggTopology(category_counts)` 的**按类别给值**模式（`topology.py:436-542`），且**类别缺省 = 历史口径**（保证既有样例建链数不变）。

## 六、接口口径（回答「多少口/什么速率」时的事实）

| GPU | 参数网 | 200G 落点 |
|---|---|---|
| H200 | 8 × 400G | 存储网（GPU 服务器 1×200G、存储服务器 4×200G） |
| B300 | 8 × 800G | 同上 |

> ⚠️ **B300 档案自相矛盾**（描述 2×400G vs 字段 8×800G），以**字段 8×800G** 为准。
> ⚠️ **Q3400 描述写 NDR，应为 XDR** —— 见到 Q3400 标 NDR 是文案缺陷。
> ⚠️ `switches/storage/` 下 5 台**全是以太网交换机、没有 IB 存储交换机** —— 缺件，不要以为查不到是自己写错了条件。

## 七、成本口径（**AL 不负责定价**）

`capacity_recommend` 返回的 `cost` 段是**启发式估算，与市价差 3–11 倍**。

→ **AL 只出「型号 + 数量 + 可追溯标注」，单价归下游报价软件。**
→ 用户问价格时：给型号和数量，明示单价需下游报价系统出。

## 常见坑

| 坑 | 正解 |
|---|---|
| 用户问「默认用什么」却去 `device_query` 里挑 | 调 `device_defaults` |
| 看到速率 `1` / `1.6` 当成真实值 | 单位解析缺陷（应为 1600） |
| 把 `breakout` 当全局开关 | 按网络角色判定 |
| 三态和不等于连接数却放行 | 是缺陷，报告 |
| 用位置参数调 `select_optical_module` | `library` 在第 5 位，必须关键字传参 |
| 报价用 AL 的 `cost` 值 | AL 只出型号+数量，单价归下游 |
| 以为 `switches/storage/` 有 IB 存储交换机 | 实际 5 台全以太，是缺件 |
