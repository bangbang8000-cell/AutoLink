# AL 结果解读与汇报

AL 的工具返回值字段多、口径杂。这个 skill 管**怎么把结果讲对**。

## 一、汇报模板

```
【设计结果】万卡-H200-QM9700-三层-IB
  规模：1250 台服务器 / 10000 卡
  参数网：IB · 400G · 三层 · QM9700 × NN 台
  存储网：IB · 400G→2×200G 分光
  收敛比：X:1
  链路：NNN 条（其中 NNN 条分光扇出）
  校验：N 项 error / N 项 warning
  机柜：1250 柜（1 柜 1 台，单柜上限 12000W）
```

**必带**：规模单位要说清是**台**还是**卡**（万卡 = 10000 卡 = **1250 台**）。

## 二、⚠️ 必须声明的三个口径

| 场景 | 必须说 |
|---|---|
| `capacity_recommend` / `atop_recommend` 结果 | **`estimated=true`，误差 ±15–20%** |
| 任何成本数字 | 启发式估算，**与市价差 3–11 倍**；单价归下游报价软件 |
| 分光 / 每服务器口数 | 现为单值口径，**GPU 与存储服务器不能分别表达**（已知缺陷 P-6） |

> 不声明 = 用户会当承诺排产。这是**对外风险**，必须说。

## 三、数字对账法（发现异常时的排查顺序）

用户说「这个数字不对」时，按这个顺序查：

```
1. 单位是不是对？          台 vs 卡（×8 差异）
2. 速率解析对不对？        '1.6T' 应为 1600，若见 1 或 1.6 → 单位缺陷
3. 口径哪条路径？          JSON 路径做 port_count−uplinks，INI 不做（有意不对称）
4. 层级判据对不对？        k²/(2p)，不是 k/(2p)（已知缺陷）
5. 三态守恒吗？            matched+not_applicable+unmatched == 连接数？
6. 键名耦合了吗？          生产者写 A、消费者读 B → 恒读 0 → 静默放行
7. 柜数怎么折的？          1 柜 1 台；按卡数折会虚高 8 倍
```

## 四、⚠️「看起来是 bug，其实是设计」清单

回答前先排除这些，**别把有意设计报成缺陷**：

| 现象 | 真相 |
|---|---|
| INI 与 JSON 算出的数不同 | **有意的不对称**（5.3.0 裁定），勿修 |
| 8 卡服务器只算 1 柜 | **正确**（默认 1 柜 1 台） |
| `apply_config_preset` 没被编译态屏蔽 | 规则锚定匹配，`preset` ≠ `reset`，**正常** |
| MC 的 `designer.py` 对 scale-up GPU 链路按无序设备对去重 | **故意**，勿改 |
| 技能数量 / 模板数量与旧文档不符 | 以**实测**为准（模板 23 套、设备 127 台、规则 22 条） |

## 五、⚠️「确实是缺陷」清单（**要如实报告**）

| 缺陷 | 表现 | 影响 |
|---|---|---|
| **P-5** | QM9700 的 breakout 把**参数网也降到 200G** | 参数网速率算错 |
| **P-6** | `storage_ports_per_server` 单值 → 建链/层级/容量三处不同源 | 层级判定与连接表对不上 |
| **P-7** | 拓扑边不带 breakout → 图与连接表口径不一致 | 图上画不出分光 |
| **二层判据** | `k²/(2p)` 被写成 `k/(2p)` → 台数差一半 | 256/1024/1250 台被误判三层 |
| **B300 档案** | 描述 2×400G vs 字段 8×800G | 以**字段 8×800G** 为准 |
| **Q3400 描述** | 写 NDR，应为 XDR | 文案缺陷 |
| **AL 权限表** | 14 个工具未登记 → 兜底 confirm | 编译态可能误伤、MCP 元数据失实 |
| **AL 权限表死条目** | `get_project_info` 等 3 个未注册 | 调用失败 |
| **`switches/storage/`** | 5 台全以太，无 IB 存储交换机 | 查不到是缺件 |

→ **报告缺陷时同步给出「那它从哪来」**（方法论 M4）。只说「不对」等于没帮上。

## 六、回答「有多少」类问题的事实表

| 问 | 答 |
|---|---|
| 工具数 | AL **72** / MC **53** |
| 能力域 | AL **13**（编译态可见 11）/ MC **11** |
| 模板 | **23** 套 |
| 设备 | **127** 台（92 硬件 + 35 光模块） |
| 校验规则 | **22** 条（V001–V022） |
| CLI action | **64** 个 |
| MCP 工具（hub 侧） | ~66 |
| `reportData` | **12** 段 |
| `schema_version` | 仍为 **2** |
| golden 基线 | **28** 个 JSON |

> 以上为实测。文档里若有旧数字，**以本表为准**。

## 七、常见坑

| 坑 | 正解 |
|---|---|
| 报「台」和「卡」混用 | 万卡 = 10000 卡 = 1250 台 |
| 不声明 estimated | 必须声明 ±15–20% |
| 把有意不对称报成缺陷 | 先查「其实是设计」清单 |
| 只报「数字不对」不说原因 | 同步给「从哪来」 |
| 用旧文档数字 | 用本 skill §6 实测表 |
| 用户问报价直接给数 | 只给型号+数量，单价归下游 |
